관리 대상

현재 runtime contract는 PROCESS_CODE = SMT|ASSY, RESOURCE_TYPE = LINE|CELL이다. 원천 line은 IP_PRODUCT_LINE이며, 리소스 row의 REF_CODE가 lineCode가 된다.

candidate → CRUD

등록 시 [라인 선택] modal이 인증 조직의 미등록 line 후보를 최대 300건 보여준다. lineName과 parentLineCode는 server canonical value로 채운다. lineCode는 수정할 수 없다.

entry·dashboard 연결

entry는 USE_YN='Y' row만 조회한다. 삭제는 OEE_OPERATION_LOG·PLAN_TIME·PRODUCTION_RESULT·DAILY_SUMMARY·DOWNTIME_EVENT 참조가 하나라도 있으면 차단한다.

등록·수정 정상 경로

  1. 인증 조직의 line 후보를 조회한다.
  2. line 선택으로 code/name/parent를 canonical form에 넣는다.
  3. SMT/ASSY와 LINE/CELL을 선택하고 저장한다.
  4. 수정은 lineCode를 유지한 채 process/type만 변경할 수 있다.
  5. 변경 시 downtime/event/log/result/summary의 process/type을 같은 transaction에서 이관한다.

삭제·실패 경로

  • resourceId와 조직으로 row를 재확인한다.
  • 다섯 원장 reference count가 모두 0일 때만 physical delete.
  • 하나라도 있으면 OEE_RESOURCE_IN_USE와 counts를 반환한다.
  • 동시 수정 중 row count가 1이 아니면 ORA-20003 경로로 실패한다.
  • 저장/삭제 후 candidate cache를 비우고 목록을 재조회한다.

04검증·source evidence

Acceptance

  • 등록 후보가 인증 조직의 IP_PRODUCT_LINE만 보여준다.
  • SMT/ASSY·LINE/CELL enum 외 payload는 400이다.
  • process/type 수정은 관련 이력을 atomic migration한다.
  • 이력이 있는 resource 삭제는 errorCode와 reference counts를 반환한다.
  • entry의 활성 OEE_RESOURCE와 resourceId/parentLineCode가 일치한다.
