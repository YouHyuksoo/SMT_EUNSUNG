02행동 규칙·오류 규칙
구분 현재 프로토타입 동작 오류·주의
카메라 마운트 후 getUserMedia({video:{facingMode:'environment'}})를 자동 요청한다. 권한/기기 실패 시 수동 입력 안내. 언마운트·재스캔 시 track과 interval 정리.
바코드 BarcodeDetector가 있으면 QR/code128/EAN13/code39/data_matrix를 400ms마다 감지한다. 미지원 브라우저는 오류 문구와 수동 입력을 보여준다. 프레임 감지 예외는 무시한다.
샘플 원천 SAMPLE_MACHINES의 E01~E05만 대문자 trim 비교로 찾는다. 존재하지 않는 code는 “찾을 수 없습니다”. 실 DB 검색이 아니다.
상태 설비를 인식하면 initDowntime()으로 RUNNING 상태를 새로 만든다. 서버의 현재 상태를 읽지 않으므로 화면 상태는 실제 설비 상태가 아니다.
토글 저장 전 한 번만 반대 상태를 선택하고, stop/resume 일시와 담당자 상수를 채운다. 미저장 토글 중 버튼을 잠그며 저장 후 다시 전환 가능하다.
저장 savedStatus만 로컬 state에 반영하고 성공 toast를 낸다. reason 필수 표시는 있으나 save 함수의 필수 검증·API 호출·DB commit은 없다.

02API·DB·계산 경계
영역 현재 구현 production 의미
API 호출 없음. api.ts, fetcher, route handler 미사용. endpoint·request/response·인증 계약을 별도 승인해야 한다.
DB Oracle entity/table을 import하지 않는다. 샘플 배열은 IMCN_MACHINE을 흉내낸 표시 데이터일 뿐이다.
시간 new Date() 서버 KST, 업무일/구간, 이벤트 start/end 정책 미정.
사용자 CURRENT_USER='관리자' 로그인 실행자·현장 작업자·감사 ID 매핑 미정.
상태 RUNNING/STOPPED 로컬 토글 backend의 RUN/DOWN 또는 OEE_DOWNTIME_EVENT와 매핑 미정.
계산 OEE·duration·업무일 계산 없음 저장·집계·분모·사유 영향은 다른 계약에서 정의.
03프로토타입 수락 기준·검증·불일치

UI Acceptance

  • 카메라 미지원/권한 실패가 수동 입력 안내로 이어진다.
  • E01 샘플 스캔 후 설비 요약과 상태 영역이 나타난다.
  • 알 수 없는 코드는 inline 오류로 남고 machine을 선택하지 않는다.
  • 상태 버튼 탭 후 미저장 상태와 시각 필드가 표시된다.
  • 저장 후에만 재토글이 가능하다.

명시적 비수락

  • 새로고침 후 값 유지
  • 다른 단말과 상태 동기화
  • DB 행·EVENT_ID 생성
  • 실제 설비 RUN/DOWN 변경
  • 오프라인 큐·재전송·중복방지

위 항목을 통과했다고 주장하지 않는다.

현재 불일치

  • 협업 요구의 dirty 재스캔 확인이 구현되지 않음.
  • 정지 사유 필수 UI와 save 검증이 불일치.
  • stopAt/resumeAt를 사용자가 편집할 수 있음.
  • 운영 사유는 샘플 DWN-*이며 승인 DB 코드가 아님.
  • 페이지 설명의 IMCN_MACHINE은 로컬 mock 주석임.
후속 결정 필요실제 저장을 추가하려면 `/oee/mobile`의 인증 Guard·조직 범위·LINE/CELL 리소스·작업자·사유·KST 업무일·idempotency를 승인된 모바일 계약에 맞추고, 현재 MOCK UI와 별도 production 구현으로 연결한다. 이 문서에는 그 API/DB를 설계한 것으로 표시하지 않는다.
