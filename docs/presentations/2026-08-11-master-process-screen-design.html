구분확인된 규칙화면 처리·주의
필수·기본processCode, processName, processType, sortOrder가 필수. 신규 기본은 type I, sort 0, start N, line *, displayGroup *.수정 시 processCode disabled. 숫자 빈 값은 null로 변환하되 sortOrder는 0으로 보정.
코드 선택공정유형·시작여부·그룹·상태·라인·부서·교대·capacity UOM·불량·기타 Y/N은 공통코드 선택을 우선한다.현재 저장값이 코드표에 없어도 “미등록 코드” 옵션으로 조용한 값 변경을 막는다.
필드 그룹기본정보, 능력(UPH/수량/효율), 시간(ST/OT/준비/대기/이동/총), 원가, 불량, 기타로 구성한다.전체 field 목록은 P2 mapping에 기록한다.
설비 배치설비는 한 공정에 속하고 배치 해제 시 UNASSIGNED_PROCESS_CODE='*'로 변경된다.구현 불일치프론트 후보는 현재 공정에 없는 모든 활성 설비라 다른 공정 설비도 이동시킬 수 있다.
삭제·갱신공정 삭제 확인, 선택 삭제 시 우측 설비 목록 비움, 저장/배치 후 count·목록 재조회.권고공정 삭제 전 배치 설비 존재 여부와 삭제 후 stale 컨텍스트를 명시적으로 검증한다.
범위공정 마스터 및 공정-설비 배치만 다룬다.품목별 라우팅/공정맵·작업지시·표준시간 별도 화면은 포함하지 않는다.

명시해야 할 mismatch

구현 불일치assignOptions는 현재 공정에 없는 모든 활성 설비를 보여 주므로, 다른 공정의 설비를 “이동”할 수 있다. UI 주석의 한 공정 원칙과 후보 차단이 다르다.

구현 불일치공정 삭제는 repository.delete이며 설비의 WORKSTAGE_CODE를 선행 해제하지 않는다. cascade/차단을 결정한다.

구현 불일치화면의 API catch는 실패를 빈 목록처럼 보일 수 있다. 실제 오류와 empty를 구분한다.
