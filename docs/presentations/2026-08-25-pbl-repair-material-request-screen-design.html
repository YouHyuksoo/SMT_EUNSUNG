Insert path

  • Group No가 없으면 cb_group_no.clicked를 trigger하고 yymmdd + seq_mat_issue_request를 표시한다.
  • 신규 detail은 sequence, request date, request status R, deficit 1, issue status N, department를 채운다.
  • inventory 선택 row가 INTERNAL이면 material MFS/item/line type을 복사한다.

Drag / report path

  • inventory column click이 drag source가 되고 request detail에 item/line을 복사한다.
  • Drag 신규 row는 request status W이며 source에서 request group no 대입이 보이지 않는다.
  • request list focus는 rowid로 detail을, group no + org로 report를 조회한다. report는 REQUEST_STATUS='W'만 읽는다.

02필수 위험 register
위험실제 근거영향 / 필요한 결정
Insert는 R, Drag는 Wue_data_control의 Insert/Append는 request_status='R', dw_2 dragdrop은 request_status='W'를 대입한다.같은 “신청”으로 보이지만 report와 후속 출고 flow가 달라진다. status 의미를 사용자에게 명시.
report는 W만 조회d_mat_request_rpt.srd retrieve SQL에 REQUEST_STATUS='W'가 고정돼 있다.Insert R row가 Preview/Print에 빠질 수 있다. report 대상 status 정책 결정.
Drag 시 group no 미설정dragdrop path는 item/line/date/sequence/status/department를 넣지만 request_group_no 대입이 보이지 않는다.group 기반 report·focus·출력에서 고아 row가 된다. drag 시 group 상속/생성 결정.
Preview 종료가 무조건 request list 복귀ivs_preview_yn='N'에서 dw_4.bringtotop=TRUE를 실행한다.inventory에서 preview를 열어도 원래 context로 복귀하지 않는다. UX 정책 보완.
Request group no 타입 불일치UI SLE와 request detail은 string/char 계열인데 report column은 number, retrieve arg는 string이다.leading zero·형변환·join/filter 오류 가능. DB/ DW/arg 타입을 하나로 결정.
종료일 자정 경계request list는 REQUEST_DATE between :arg_dateset and :arg_dateend를 사용한다.dateend 00:00:00이면 종료일 row가 누락될 수 있다. 업무일/포함 경계 고정.
출고 후 잠금 / 완료 삭제 제한request_status C는 delete 차단, issue_qty > 0은 여러 detail field protect 조건을 사용한다.잠금 기준이 request_status와 issue_qty로 이원화된다. 실제 출고 transaction과 일치 확인.
packing qty 이벤트와 실제 DW 컬럼 불일치itemchanged는 request_qty_org를 검사하지만 DW 선언은 request_qty 중심이다.포장 단위 자동 보정이 실행되지 않거나 잘못된 event가 된다. column/event 일치 보완.

수락 기준

  • Inventory tree → request detail drag/insert, group rail, request list focus, report preview가 실제 PB 화면과 같은 순서로 동작한다.
  • Insert R와 Drag W를 실제 DB row에서 구분하고 report W-only 결과를 확인한다.
  • Drag row의 group no, report type, 종료일 경계, print/preview context를 fixture로 재현한다.
  • 출고 후 issue_qty 잠금과 request_status C 삭제 제한을 실제 update/delete 시도로 검증한다.
  • packing qty event가 실제 DW column에 연결되고, 계산된 request_qty가 DB 저장값과 일치한다.
  • Oracle SQL 오류 원문·empty·rollback을 화면에서 구분한다.
