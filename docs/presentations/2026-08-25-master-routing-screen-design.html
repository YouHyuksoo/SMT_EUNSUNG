04ProcessSelect 직접 영향과 간접 영향

직접 영향공정 modal

  • 공정 modal의 ProcessSelect가 /master/processes?limit=5000를 호출하며 options가 로딩 중이면 Select가 disabled다.
  • 선택값 processCode는 routing process body의 workstageCode로만 저장된다. 공정명은 별도 입력·저장하지 않는다.
  • 공정마스터의 tenant·삭제·응답 empty가 등록 가능 코드 집합을 직접 결정한다.

간접 영향목록·BOM·자재

  • GET processes 목록은 entity property와 frontend type의 seq 계약을 별도로 가진다. selector가 정상이어도 process row selection은 이 응답 계약을 통과해야 한다.
  • BOM page의 nested routing panel도 first.seq를 읽으므로 같은 process sequence 불일치 영향이 전파된다.
  • material API는 선택된 seq path에 의존하므로 process row가 올바르게 선택되지 않으면 자재 조회/저장이 연결되지 않는다.

03DB·auth·validation

IP_ROUTING_* DB 계약

  • IP_ROUTING_GROUPS: PK (ORGANIZATION_ID, ROUTING_CODE), item FK, Y/N check, active item function-based unique index.
  • IP_ROUTING_PROCESSES: PK (ORGANIZATION_ID, ROUTING_CODE, PROCESS_SEQ), group/workstage/supplier FK, positive seq, INTERNAL/SUBCON, supplier/time/job/use checks.
  • IP_ROUTING_MATERIALS: PK (ORGANIZATION_ID, ROUTING_CODE, PROCESS_SEQ, CHILD_ITEM_CODE), process/item FK, UK_IP_RM_CHILD, ALLOC_QTY>0, issue method check.

인증·공정 참조

  • RoutingGroupController와 ProcessController는 클래스에 @UseGuards(JwtAuthGuard)가 있고 모든 current method가 @OrganizationId()를 사용한다.
  • service validateProcessRefs()는 선택된 workstageCode를 같은 조직의 ProcessMaster에서 찾고, SUBCON이면 supplier도 같은 조직에서 찾는다.
  • ProcessSelect는 showProcessType false지만 useComCodeMap("WORKSTAGE TYPE")를 호출한다. type은 라벨에 포함하지 않고 option raw contract만 유지한다.
04확인된 위험·개발 DB 불일치

BLOCKER · source/docs evidenceIP_ROUTING vs 개발 DB

현재 backend entity·migration·service는 IP_ROUTING_GROUPS, IP_ROUTING_PROCESSES, IP_ROUTING_MATERIALS를 사용한다. 그러나 docs/reports/oee-mobile-collaboration/2026-08-23-production-linked-oee-review.md:L84-L105는 개발 DB에 이 세 테이블이 없고, 개발 DB의 ROUTING_GROUPS / ROUTING_PROCESSES / ROUTING_MATERIALS와 legacy tables가 모두 0건이라고 기록한다.

이 작업에서는 DB connector로 재측정하지 않았으므로 위 문서 증거를 “확인된 위험”으로만 표시한다. 실제 CRUD 완료 기준은 코드 원장과 개발 DB 공식 계약을 coordinator가 통일·검증하는 것이다.

BLOCKER · response shapeprocessSeq ↔ seq

  • backend entity/service response는 processSeq; frontend RoutingProcessItem/SelectedProcess와 manager/material editor는 seq를 읽는다.
  • service의 findProcesses()와 controller에 alias mapper가 없고, test fixture도 processSeq를 반환한다.
  • 따라서 group process 목록·first auto-select·edit/delete/material path의 현재 동작은 HTTP response로 확인하기 전 완료 처리하지 않는다.
05수락 기준과 source evidence

재검증 시나리오

  • 인증된 조직으로 group → process master option → process create/update → process list response의 property를 순서대로 확인한다.
  • SUBCON supplier 누락, process master 미존재, 시간/seq 범위 오류가 API error로 보존된다.
  • 현재 BOM 밖 자재·타 공정 배정·중복 mutation이 차단되고, positive allocQty와 issueMethod가 재조회 후 일치한다.
  • process list response가 frontend seq contract와 실제로 일치하는지, IP_ROUTING_*가 개발 DB에 존재하는지 확인한다.
  • routingCode=itemCode, LABEL_ISSUE_YN은 현재 구현이 아닌 승인 docs의 후속 범위로 분리한다.
