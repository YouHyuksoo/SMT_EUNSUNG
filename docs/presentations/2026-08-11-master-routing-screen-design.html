01요구사항 및 정보 계층

목적

품목에 연결된 라우팅 그룹을 선택하고, 10 단위 공정 순서와 실행유형·작업지시 여부를 관리한다.

선택 공정의 현재 BOM 자재를 배정·해제하고 투입방식을 저장한다.

사용자

생산기술·공정 기준정보 담당자. 품목 선택, 라우팅 등록/수정/삭제, 공정 등록/수정/삭제, 자재 저장을 수행한다.

외주(SUBCON)는 공급처가 필수이며 SupplierSelect로 선택.

3단 구조

GROUP 라우팅 코드·품목·명칭 → PROCESS 순번·공정 → MATERIAL BOM 자재·배정 공정.

페이지 우측 material editor는 공정을 선택했을 때만 열린다.

03비즈니스 규칙
구분규칙화면·서버 처리
활성 그룹같은 조직·품목에는 활성(USE_YN='Y') 라우팅을 하나만 둔다.생성/활성화 시 서버가 선행 검사. UI는 그룹 code·품목을 수정 시 disabled.
공정PROCESS_SEQ는 양수. 신규 기본 순번은 현재 최대값+10. 공정 master 참조가 유효해야 한다.실행유형 INTERNAL/SUBCON, 작업지시 Y/N, 표준·준비시간 0 이상. SUBCON이면 공급처 필수.
자재 배정현재 유효 BOM 자재만 배정. 한 자재는 라우팅 내 한 공정에만 배정, 투입수량은 0보다 커야 한다.BOM 불일치·다른 공정 배정은 checkbox/input을 차단. 저장은 upserts/deletes 묶음.
삭제공정이 있는 그룹은 삭제 금지. 투입자재가 있는 공정은 삭제 금지.ConfirmModal 후 서버 Conflict 메시지를 toast로 표시한다.
조직·동시성모든 그룹/공정/자재는 조직 ID로 격리하며 선택 context가 바뀐 오래된 응답은 버린다.controller는 JwtAuthGuard, service는 transaction/lock과 request generation을 사용한다.

03DB·검증·완료 기준

DB / transaction

  • IP_ROUTING_GROUPS PK 조직+ROUTING_CODE; 활성 품목 하나 제약을 서비스가 검사한다.
  • IP_ROUTING_PROCESSES PK 조직+코드+PROCESS_SEQ; 그룹 lock 후 생성/삭제한다.
  • IP_ROUTING_MATERIALS는 child unique/index와 process FK. 삭제·재정렬은 자재 count와 함께 transaction.
  • 자재 저장은 현재 유효 ID_ENG_BOM.DATESET/DATEEND를 재확인하고 양수 수량만 허용한다.

수락 시나리오

  • 그룹 선택이 공정 목록과 material context를 함께 교체하고 이전 응답이 새 선택을 덮지 않는다.
  • SUBCON에서 공급처 없이는 저장되지 않으며 INTERNAL 전환 시 공급처를 저장하지 않는다.
  • 현재 BOM 밖 자재·다른 공정 배정 자재는 선택/수정이 차단된다.
  • 양수 allocQty와 issueMethod를 저장하고 재조회 후 dirty가 해제된다.
  • 하위 공정/자재가 있는 삭제는 서버가 거부하고 UI가 계층을 유지한다.
04현재 구현 불일치 및 백엔드 전용 동작

불일치계약·navigation

  • backend에는 legacy RoutingController /master/routings와 PROCESS_MAPS가 있으나 현재 page는 사용하지 않고 routing-group 계약만 사용한다.
  • BOM 화면이 /master/routing?itemCode=...로 이동시켜도 RoutingPage는 query를 읽지 않아 해당 품목을 preselect하지 않는다.
  • 현재 UI에는 공정 reorder, useYn query filter가 없다. material dirty guard도 routing page 수준에서는 제공하지 않는다.

백엔드 전용현재 UI action 없음

  • PUT /{code}/process-order: 전체 공정·자재 순번을 임시 번호로 transaction 재배치.
  • GET /master/routings legacy 목록·상세 및 CRUD.
  • 그룹 상세 GET /master/routing-groups/{code}는 현재 list 선택으로 대체되어 직접 호출하지 않는다.
  • 서비스의 row lock, current BOM overlap 검사, Oracle IN chunking은 UI가 아닌 서버 안전장치다.
