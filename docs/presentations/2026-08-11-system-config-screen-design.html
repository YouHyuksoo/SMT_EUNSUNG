01요구사항 및 기능

목적

그룹 탭으로 설정을 좁히고, 각 row의 현재 값을 변경한 뒤 변경 건수를 표시하는 일괄 저장을 수행한다. 신규 등록/삭제도 제공한다.

그룹 구조

전체, MATERIAL, PRODUCTION, QUALITY, SYSTEM, AI, AI_EMBEDDING 탭. AI는 LLM 전용, Embedding은 knowledge/reindex 전용 panel이다.

현재 계약 주의

불일치ISYS_CONFIG에는 group/type/options/sort 컬럼이 없어 service가 view에서 파생한다. Add modal의 타입/옵션/정렬이 그대로 영속된다고 가정하지 않는다.

03비즈니스·구현 규칙
구분규칙/현재 사실화면 처리
일반 rowBOOLEAN은 Y/N toggle, SELECT는 options JSON, NUMBER/TEXT는 Input이라는 프론트 규칙이다.backend view가 현재 value로 type을 추론하므로 기존 SELECT/options가 TEXT/null이 될 수 있다.
전체 탭page의 전체 filter는 configGroup !== 'AI'만 적용한다. AI/Embedding 전용 패널이 별도다.현재 group별 표시와 service infer 결과를 그대로 보존한다.
일괄 저장changes의 id/value만 PUT /system/configs/bulk로 전송한다.변경 수가 0이면 저장 disabled; 성공 시 map reset/invalidate/refetch/store fetch.
AI panelprovider/model/enabled/key를 /ai/test와 config upsert로 관리한다. key 원문은 조회하지 않는다.저장/연결 테스트 자체 toast; 실패는 panel toast.
Embeddingprovider/model/dims, localStorage 대상, status/reindex/search test를 별도 관리한다.reindex는 최대 10분 timeout, 대상 1개 이상, 성공 chunks 표시.
오류일반 save/delete는 local catch가 없어 Axios 전역 오류 모달로 흐를 수 있다. store bootstrap은 suppress modal + warn.현재 오류 처리 분산을 유지하고 silent fallback을 성공으로 표시하지 않는다.

03DB·검증·수락 기준
영역현재 확인수락 기준
tenant관리 list/create/update/bulk/delete는 organization scope를 사용하지만 active endpoint는 service에서 전체 active를 조회한다.관리 API가 다른 조직 값을 노출/수정하지 않는지 확인하고, active global semantics는 별도 결정한다.
value/typeY/N·숫자 추론은 value 기반; SELECT options는 entity에 없어 null로 view된다.현재 row가 실제 응답 type에 따라 렌더되고, 타입/옵션 보존을 요구하는 경우 계약 결정을 차단 항목으로 보고한다.
저장bulk는 configKey 기준 update 후 updated row를 반환한다. label/description/options/sort는 bulk에서 변경하지 않는다.변경 count가 맞고 성공 후 list/store가 재조회된다. 부분 실패/원자성은 별도 서비스 계약 검증 대상이다.
AI/secretAPI key 입력은 저장 후 clear, status는 configured 여부만 표시한다.원문 key가 list/응답/문서에 노출되지 않고 test/reindex 결과가 자체 메시지로 표시된다.
오류store active fetch는 suppress modal + console.warn; 일반 save/delete는 local catch 없음.기본 부트스트랩이 실패해도 앱이 동작하고, 관리 저장 실패는 성공 상태로 reset하지 않는다.
