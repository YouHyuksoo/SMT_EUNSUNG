비즈니스 규칙

  • 달력 day type은 WORK/OFF/HALF/SPECIAL; OFF일 때만 offReason을 전송한다.
  • workMinutes를 비우면 서버가 적용 shift에서 자동 파생한다. 명시값은 override다.
  • 확정 CONFIRM_YN='Y' 행이 target 범위에 하나라도 있으면 저장·생성·복사를 거부한다.
  • 연간 생성은 주말과 양력 고정공휴일만 자동 OFF로 처리한다. 음력·대체공휴일은 자동 생성하지 않는다.

인증·조직·감사

  • 활성WorkCalendarController와 ShiftTimeController 모두 class-level JwtAuthGuard.
  • 활성read/write는 @OrganizationId()를 service에 넘기고, write는 @UserId()를 audit field에 사용한다.
  • 활성frontend line option은 ProdLineSelect → useProdLineOptions → /master/prod-lines?limit=1000이다.
  • 확인ProdLineController 자체에는 이 파일에서 class-level guard가 보이지 않으므로 global guard 정책과 tenant isolation을 별도 확인한다.
Oracle safetyOracle DATE가 문자열로 hydrate되는 회귀 때문에 shift update/delete와 calendar confirm은 save/remove 대신 criteria update/delete 및 transaction delete+insert를 사용한다.
03위험·stale·결정 필요

source/운영 위험

  • 확정 범위DTO는 month를 지원하지만 현재 UI confirm/unconfirm은 year+lineCode만 보내 연 전체를 확정/취소한다. 월 단위 action으로 문서화하지 않는다.
  • line override와 PL/SQLbackend merge는 line row를 우선하지만 F_GET_DELIVERY_DATE snapshot은 company calendar만 읽고 HOLIDAY_YN을 사용한다. line 예외가 납기 계산에 반영되는지는 결정/실데이터 확인이 필요하다.
  • stale help commentWorkCalendarFieldHelp.tsx 상단 설명에 과거 HANES table명이 남아 있으나 실제 constants와 entity는 IP_ 모델이다. 구현 문서에서는 stale 이름을 정본으로 사용하지 않는다.
  • live DBmigration 파일과 entity가 존재해도 Oracle에 적용된 row/constraint/PLSQL validity는 별도 확인 전에는 완료로 판정하지 않는다.

수락 시나리오

  • 현재 월과 year draft가 일치하고, 4자리 전에는 400/API error modal이 생기지 않는다.
  • ProdLineSelect 선택 후 days·summary query에 동일 lineCode가 들어가고 line source badge가 표시된다.
  • OFF만 offReason을 노출·저장하고, blank workMinutes가 shared shift rule로 파생된다.
  • 확정 날짜는 cell click/save/generate/copy가 차단되고 unconfirm 후에만 다시 편집된다.
  • generate/copy/bulk가 delete+insert transaction과 내부 confirm 재검사를 거치는지 focused test와 Oracle trace로 확인한다.
  • 교대시간 overlap, DATESET 첫날, 야간 cross-midnight, dateend null, audit user를 검증한다.
