01요구사항 및 기능

목적

부서 목록을 코드/명칭으로 검색하고, 상위부서 선택을 포함한 CRUD를 우측 패널에서 수행한다. 목록은 DataGrid export/filter를 제공한다.

업무 사용자

시스템/조직 관리자. 동일 조직의 부서만 API에서 조회·변경하며, 부서 코드는 수정 시 불변이다.

현재 persistence 주의

불일치폼/DTO에는 sortOrder, managerName, useYn이 있지만 실제 DepartmentService.toView는 0/null/Y를 파생하고 저장 서비스도 이 값을 쓰지 않는다.

03비즈니스·구현 규칙
구분규칙/현재 사실화면 처리
필수·키deptCode, deptName 필수. 수정 시 deptCode disabled. 조직 + 코드가 DB 복합 PK다.두 값이 비어 있으면 저장 disabled; 서버 DTO도 code/name을 검증한다.
상위부서사용 중(useYn=Y)이고 현재 자신이 아닌 부서만 select option으로 만든다. 공백은 *로 저장·view에서는 null이다.“없음” option을 첫 항목으로 제공한다.
보조 필드sortOrder 기본 0, managerName, remark, useYn을 폼/DTO가 노출한다.현재 서비스는 remark만 실제 entity에 매핑하고 나머지는 view 기본값/무시다.
오류목록·삭제 catch가 ignore. 패널 저장은 서버 message를 inline에 표시한다.조회 실패와 0건은 emptyMessage에서 구분되지 않는 현재 동작을 보존한다.
삭제삭제 전 대상 부서명을 ConfirmModal로 확인하고 API DELETE를 호출한다.실패 시 deleteTarget이 남을 수 있으며 catch는 오류를 표시하지 않는다.

03DB·검증·수락 기준
영역현재 확인수락 기준
tenantcontroller의 @OrganizationId()와 service where에 조직 ID가 포함된다.조직이 다른 동일 deptCode의 행에 접근하지 않는다. controller guard 적용 여부를 인증 설정과 함께 확인한다.
키/필수deptCode/name 필수; 수정 path는 기존 code; DTO 길이/정수/USE_YN 검증.중복 code는 409, 빈 필수값은 저장 전/서버에서 차단, code는 수정 불변.
계층parent는 활성 목록에서 자기 자신을 제외하지만 순환 계층 방지는 service에 없다.현재 범위는 자기 선택 방지까지; 순환/삭제 참조 차단은 별도 결정으로 테스트한다.
스키마 mismatchISYS_DEPARTMENT에 use/sort/manager 컬럼이 없고 service가 이 값을 파생한다.화면 설명에서 해당 값을 영속 필드로 단정하지 않는다. 실컬럼 기준 계약 확정 후 개선한다.
오류list/delete는 catch ignore, 저장은 inline message.저장 실패 시 입력 유지; 조회 실패를 0건으로 오인할 위험을 residual risk로 남긴다.
