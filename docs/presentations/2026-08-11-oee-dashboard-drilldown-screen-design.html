02업무 규칙·범위
규칙 확정 동작 표현·예외
공정 목록 드롭다운은 SMT, PERF, COAT, ROUTER, ASSY, PACK 6개를 하드코딩한다. 백엔드 조회 가능 공정의 SSOT가 아니므로 값 추가 시 UI와 API를 함께 확인한다.
일자 초기값은 URL date 또는 브라우저 오늘이며 입력 최대값은 오늘이다. 입력 변경은 state와 SWR key만 바꾸고 URL을 다시 쓰지 않는다.
조회 계층 백엔드가 당일 이상을 live, 과거를 snapshot으로 반환한다. 과거 409는 “집계 미생성(마감 필요)”이며 fallback 없음.
정렬·색상 SQL이 ORDER BY v.OEE로 오름차순 반환한다. 낮은 리소스가 위에 먼저 보이며 OEE ≥85 초록, ≥60 황색, 미만 적색.
상세 정보 tooltip에 OEE, 가동, 성능, 양품, UPH, 계획달성, 가동/비가동분을 표시한다. 표·CSV·리소스 상태 변경·드릴다운 2단계는 범위 밖이다.
빈 상태 200 + rows=[]면 공정명과 함께 데이터 없음 메시지를 표시한다. 로딩 중 문구와 진짜 빈 결과를 구분한다.

03DB·계산·수락·불일치

DB 및 계산

  • 당일 이상: V_OEE_LIVE에서 RESOURCE_ID, PROCESS_CODE, A/P/Q/OEE, UPH, PLAN_ACHIEVE, RUN_MIN, DOWNTIME_MIN, OUTPUT_QTY.
  • 과거: 동일 컬럼셋의 OEE_DAILY_SUMMARY.
  • JOIN OEE_RESOURCE r ON r.RESOURCE_ID=v.RESOURCE_ID로 이름을 붙인다.
  • OEE는 view/procedure에서 가동×성능×양품. 화면은 재계산하지 않는다.
  • 수락: source 선택, 낮은 OEE부터 정렬, tooltip 값 일치.

Acceptance

  • 종합 링크로 들어오면 query 공정/일자가 초기 선택된다.
  • 공정·일자 변경마다 올바른 GET key로 재조회한다.
  • 200 rows는 막대 높이와 이름/퍼센트를 렌더한다.
  • 409 과거 미마감은 “집계 미생성” 상태다.
  • 0행은 “데이터가 없습니다” 상태다.
  • DB/API의 리소스 순서와 화면 순서를 비교한다.
확인 필요 · @Public/조직OeeController 전체가 @Public()이며 dashboard service의 overview/drilldown SQL에 ORGANIZATION_ID filter가 없다. OEE_RESOURCE join도 조직으로 제한하지 않는다. 현재 단일 조직 seed 전제와 인증형 메뉴가 함께 존재하므로, 운영 전 Guard·조직 주입·SQL scope를 결정해야 한다.
