02업무 규칙·검증 규칙
구분확정 동작화면·서버 주의
시간 분류ST, CT, NT, TT 네 컬럼을 초 단위로 관리한다.각 값은 number input step 0.1/min 0. 화면은 0이면 “-”로 표시한다.
모델 선택직접 코드 입력이 아니라 GET /oee/standard-time/items 팝업에서 단일 선택한다.모델코드·명·규격을 검색하고 최대 300건을 표시한다.
기간적용 시작일 필수, 종료일 미입력은 화면에서 9999-12-31 현재 적용으로 보낸다.종료일이 시작일보다 빠르면 저장 차단. 기간 겹침/유효행 검사는 현재 backend에 없다.
최소 입력모델·시작일·하나 이상의 양수 표준시간이 필요하다.현재 차단은 프론트 함수에만 있으며 browser alert()를 사용한다.
수정원본 모델/시작일을 함께 보내 새 키 변경을 지원한다.서비스는 트랜잭션 내 원본 DELETE 후 INSERT. 중복 키는 409.
목록 일관성저장 성공 후 drawer를 닫고 GET으로 목록을 재조회한다.실패 시 입력 drawer를 유지하고 서버 message 우선 toast.

03DB·계산·Acceptance·Mismatches

DB 키IP_PRODUCT_ST_MASTER(ITEM_CODE, DATESET, ORGANIZATION_ID)DATEEND/ST_VALUE/CT_VALUE/NT_VALUE/TT_VALUE/REMARK 및 enter/modify 감사 컬럼
모델 명LEFT JOIN ID_ITEM ON ITEM_CODE + ORGANIZATION_IDmodelName/spec는 참조 표시, 저장 payload에는 code만
기간 표시periodText(from,to), OPEN_END='9999-12-31'종료 공란을 현재 적용으로 표시
OEE 계산이 화면은 OEE를 계산하지 않고 표준시간을 저장한다.어떤 집계가 CT/ST를 참조할지는 별도 OEE/production 계약으로 확인
저장 트랜잭션중복 확인→(edit이면 원본 DELETE)→INSERT키 변경 중 실패 시 manager transaction rollback
확인 필요 · @Public/하드코드 조직StandardTimeController에 @Public()이 있고 Guard/조직 decorator가 없다. StandardTimeService는 const ORG = 1, 기본 사용자 ADMIN을 사용하며 DTO의 optional userId를 body에서 받을 수 있다. 인증 사용자·조직을 서버 권위로 바꿀지 결정해야 한다.

Acceptance

  • 초기 목록/로딩/빈 목록이 구분된다.
  • 모델 picker 검색·선택이 code/name을 채운다.
  • 네 시간 중 하나 이상 양수만 저장된다.
  • 수정 성공 후 목록이 재조회된다.
  • 중복 409의 서버 message가 표시된다.

Mismatches

  • 계획은 개방형 sentinel 2099-12-31, UI/service는 9999-12-31.
  • entity DATEEND는 nullable지만 DTO는 validTo 필수.
  • 페이지는 DELETE endpoint를 노출하지 않음.
  • 기간 겹침/as-of 검증이 없음.
  • 프로젝트 규칙과 달리 client validation이 alert 사용.
