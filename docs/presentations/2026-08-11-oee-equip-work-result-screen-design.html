03Validation·Acceptance·Mismatches

Prototype Acceptance

  • 행 선택 전 세 액션이 안내 toast를 낸다.
  • 실적 패널의 기본값이 선택 row에서 복사된다.
  • 실적 저장 후 해당 row의 수치/완료/수정자/시각이 갱신된다.
  • 불량 panel에 10개 유형과 qty/remark가 보인다.
  • 비가동 토글은 저장 전 잠기고 저장 후 재토글 가능하다.
  • 패널 close 후 기본 목록이 유지된다.

현재 validation

  • HTML number의 min=0은 UI 힌트이며 save 함수가 값을 검증하지 않는다.
  • 불량 합계가 실적수량을 넘는지 검사하지 않는다.
  • 비가동 사유 선택 필수 표시만 있고 저장 차단이 없다.
  • 시각 역전·미래·중복·권한 검사가 없다.
  • dirty close confirmation이 없다.

Mismatches

  • “실적등록” 명칭과 실제 local patch 사이에 계약 차이.
  • 불량 입력에는 저장 action이 없어 성공 경로가 없다.
  • 가동/정지 UI의 RUNNING/STOPPED와 backend RUN/DOWN 미매핑.
  • seed의 current user/회사 값은 실제 auth/tenant가 아님.
  • 설계 spec의 OEE 독립 테이블을 조회하지 않음.
production 전 차단이 mock을 API-backed 화면으로 승격할 때는 별도 요구 승인과 테스트가 필요하다. 현재 문서는 API path, DB table write, @Public/조직 권한을 설계 완료한 문서가 아니다.
