01요구사항 및 사용자

목적

기준일 기준 유효 판매가격을 고객·품목·제품라인유형으로 조회하고 원화/외화 가격과 변경사유를 저장한다.

기본 dateend는 2999-12-31이며 validOnly가 기본 true다.

식별자

customerCode + itemCode + productLineType + dateset + organizationId 자연키를 사용한다.

수정 시 customer/item/productLineType은 잠기고 originalDateset을 보낸다.

영향·권한

신규 시 같은 고객·제품·라인의 기존 적용 row를 impact로 확인한다. 조직·승인 감사값은 server 권한이다.

승인/삭제 mutation은 현재 계약에 없다.

03DB·검증·완료 기준

DB / 서버 불변식

  • IS_PRODUCT_SALE_PRICE PK는 customer/item/productLineType/dateset/organization.
  • 목록은 ID_ITEM과 ICOM_CUSTOMER를 같은 조직으로 join한다.
  • DTO는 customer/item/line length, date, optional number 0 이상, originalDateset을 검사한다.
  • oracleError는 driver message를 BadRequest로 보존하고, 승인 컬럼은 이 서비스의 mutable에 포함하지 않는다.

수락 시나리오

  • 기준일·유효 checkbox·고객·품목·제품라인 filter가 SQL과 일치한다.
  • 신규/수정 impact 확인 전에 저장 API가 호출되지 않는다.
  • 수정 시 customer/item/line key가 보존되고 originalDateset로 정확히 갱신된다.
  • 가격/세율 음수·잘못된 date·중복/없는 key 오류가 성공처럼 보이지 않는다.
  • 저장 후 panel close 및 reload, 통화/코드 badge와 approval read-only가 유지된다.
04현재 구현 불일치 및 백엔드 전용 동작

불일치필터·impact

  • SalePriceQueryDto에는 priceType이 있지만 SalePricePage toolbar에는 priceType select가 없어 직접 필터할 수 없다.
  • getImpact(update)는 closingRows를 빈 배열로 반환한다. 신규와 수정의 영향 메시지는 같은 정보량을 갖지 않는다.
  • 폼의 impact 호출은 별도 error boundary 없이 API exception이 발생할 수 있으므로 오류 surface를 검증 대상으로 남긴다.
  • controller에 DELETE/approval endpoint가 없어 UI도 삭제/승인을 제공하지 않는다.

백엔드 전용현재 UI에 없는 동작

  • priceType query filter 및 고객 검색 limit contract.
  • confirmBy/confirmDate/priceChangeConfirmYn의 저장·조회 audit 정보.
  • 조직 필터와 Oracle 오류 변환, repository update의 affected 검사.
  • 실제 기간 마감/가격 영향에 대한 DB trigger 또는 외부 처리 여부는 현재 service source만으로 확정하지 않는다.
