비가동 전이의 안전선과 현재 계약의 차이

서버가 권위자인 상태 전이, 테넌트 격리, 실패 재시도, 그리고 CELL 계약을 구현 전 검증 대상으로 고정한다.

정상 경로

  1. worker ID 확인 성공 → process 선택.
  2. active OEE_RESOURCE와 사유를 로드 → resource 선택.
  3. status에서 열린 event가 없으면 RUNNING, 있으면 DOWNTIME.
  4. RUNNING에서 사유를 선택해 start, DOWNTIME에서 종료 confirm.
  5. 서버 응답 event를 반영하고 status를 재조회한다.

잠금·오류 경로

  • 작업자/공정/resource가 없으면 다음 단계 버튼이 잠긴다.
  • 네트워크 offline, status 오류/로딩 중이면 전이를 차단한다.
  • 409는 conflict 안내 후 최신 status를 다시 읽는다.
  • DOWNTIME 중 worker/process/resource 변경은 contextLocked로 차단한다.
  • reason/memo 오류는 draft를 유지하고 재시도한다.

03현재 코드와 승인 계약의 차이
ASSY CELL 확인 필요: 승인된 선행계약은 조립 CELL의 실제 원천을 PLANTS로 보고 CELL이 없으면 라인으로 우회하지 않도록 했다. 그러나 be15942의 OeeMobileService.listLineResources()는 SMT와 ASSY 모두 OEE_RESOURCE + IP_PRODUCT_LINE을 사용하고, parentLineCode=resourceCode=REF_CODE를 강제한다. 실제 PLANTS CELL/상위라인을 적용할지 결정이 남아 있다.
관리 화면 의존: entry가 빈 리소스를 해결하는 화면은 /oee/master/resource다. 리소스 master의 line candidate·유형·공정 계약이 바뀌면 entry의 선택 identity와 이벤트 조회 조건이 동시에 바뀐다.
04검증·source evidence

Acceptance

  • 작업자·공정·활성 OEE_RESOURCE LINE/CELL·parentLineCode가 모두 표시된다.
  • RUNNING에서 시작, 열린 event에서 종료, 이력 재조회가 완료된다.
  • 동일 requestId는 replay되고 중복 시작/종료는 409가 된다.
  • 인증 organizationId 경계를 벗어난 resource와 worker는 거부된다. 시작 명령은 인증 company/plant/executor도 필요로 한다.
  • ASSY CELL 원천이 PLANTS인지 현재 OEE_RESOURCE line mapping인지 명시된다.
