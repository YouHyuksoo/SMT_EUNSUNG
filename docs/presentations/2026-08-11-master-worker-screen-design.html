01요구사항과 사용자

목적

확인작업자 코드·이름·부서·직급·연락처·입퇴사·QR·사진·사용여부를 등록·수정한다. 목록에는 아바타와 핵심 인적 필드를 표시한다.

QR 조회는 PDA 연동용 별도 API로 제공된다.

사용자·권한

추정인사/생산 마스터 관리자 또는 현장 관리자. 역할명은 소스에 직접 선언되지 않고 요청의 조직 ID로 범위를 제한한다.

확인작업자 CRUD·QR 조회·사진 upload endpoint가 backend에 있다.

핵심 결과

코드/이름 검색, 사용여부 공통코드 필터, 사진·이름·부서가 있는 grid.

사진은 클릭/drag&drop으로 업로드하고 원형 preview·삭제를 제공한다.

03업무 규칙·범위 경계
구분확인된 규칙화면 처리·주의
필수·키workerCode 신규 필수·최대 50, workerName 필수·최대 100. 수정 시 코드 disabled.조직 ID와 함께 자연키로 조회·변경한다.
기본정보engName, dept, position, phone, email, qrCode, remark 선택. 부서는 DepartmentSelect, 직급은 JOB_POSITION 코드 선택.코드성 직급은 자유 입력 대신 공통코드 라벨을 사용한다.
작업자 유형frontend type에는 CUTTING/CRIMPING/ASSEMBLY/INSPECTOR/PACKING/LEADER와 색상 상수가 있다.구현 불일치현재 backend entity/DTO와 form/grid는 workerType을 저장·표시하지 않는다.
근무정보hireDate, quitDate는 YYYY-MM-DD, useYn은 Y/N.퇴사일이 입사일보다 빠른지 추가 검증 권고.
사진이미지 MIME, 5MB 제한; backend field는 file, 성공 response URL을 form의 photoUrl로 저장한다.클릭/drag&drop·upload spinner·원형 preview·삭제. 실제 crop modal은 현재 구현되지 않는다.
공정 배정DTO에는 processIds?: string[]와 CLOB JSON 저장 규칙이 있다.구현 불일치현재 작업자 form에는 processIds 입력/배정 UI와 payload가 없다. 화면에 임의로 추가하지 않는다.
삭제·변경 보호삭제 확인과 useUnsavedGuard를 사용한다.삭제 service는 repository.delete; soft delete를 전제하지 않는다.

04수락 기준
  • 조직별 작업자만 목록에 나오고 search/useYn query가 DB와 일치한다.
  • 작업자 코드/이름 필수, edit에서 코드 immutable, 중복 409를 표시한다.
  • 사진 upload의 field·MIME·5MB 제한과 URL 저장 순서를 검증한다.
  • QR 또는 작업자 코드 조회가 기대 workerCode/name/dept를 반환한다.
  • 입력·사진 변경 dirty guard와 saving/error 상태가 유실을 막는다.
  • processIds 배정과 crop modal은 구현 승인 전 수락 기준에 넣지 않는다.

명시해야 할 mismatch

구현 불일치DTO/entity/service는 processIds CLOB JSON을 지원하지만 WorkerFormPanel은 이를 입력·payload에 포함하지 않는다.

구현 불일치WorkerPhotoUpload 주석의 crop/zoom 모달이 실제 코드에는 없다. crop을 설계 기능으로 표시하지 않는다.

구현 불일치사진 upload가 작업자 식별자 없이 먼저 파일을 만들 수 있어 orphan 파일 정리 정책이 필요하다.
