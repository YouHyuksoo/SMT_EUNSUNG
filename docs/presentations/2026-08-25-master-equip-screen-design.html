업무 목적

확인IMCN_MACHINE의 설비코드·설비명·설비유형·적용공정·제조사·모델·사진·상태·사용여부를 조직 단위로 관리한다. 통신 필드는 UI에 있으나 현재 service가 필터·저장하지 않는다.

적용공정은 라인이 아니라 WORKSTAGE_CODE이며, grid 필터와 편집 폼 모두 공정 selector를 사용한다.

코드성 값

확인설비유형 선택지는 공통코드 MACHINE TYPE에서 로드하지만 grid cell은 프론트 번역 fallback 또는 원시 코드를 표시한다. 통신 필터·폼은 COMM_TYPE 공통코드를 쓰지만 backend service는 해당 값을 적용하지 않는다.

완료로 쓰지 않을 것

불일치설비 BOM 컴포넌트와 backend controller/service/entity는 존재하지만 MasterEquipModule에 BOM controller가 등록되어 있지 않다. 따라서 BOM은 UI 계약/미활성 위험으로 표시한다.

패널 상태 규칙

  • 설비 edit와 BOM panel은 동시에 열지 않는다.
  • edit 패널이 dirty면 행 전환·취소에 guard modal이 개입한다.
  • 저장 버튼은 equipCode + equipName + equipType가 모두 채워질 때만 활성화된다.
  • 통신 상세의 “표시”와 “저장”을 분리한다. 현재 저장 payload에 Topic/Serial/Baud는 없다.
  • BOM 재고는 stockQty ≤ safetyStock일 때 화면에서 red 강조되지만, 그 UI route가 실제로 활성인지 먼저 확인한다.
결정 필요“설비 BOM까지 활성 기능”이라고 발표하려면 controller 등록, guard, tenant 인자, 실제 DB table 존재를 먼저 검증해야 한다.

인증과 조직 격리

  • 활성EquipMasterController는 class-level JwtAuthGuard이며 모든 기본 API가 @OrganizationId()를 받는다.
  • 주의EquipBomController에는 class-level guard가 없고, MasterEquipModule controllers에는 EquipMasterController만 있다.
  • 서비스는 기본 설비 경로에서 request body 조직 ID를 사용하지 않고 controller decorator 값을 넘긴다.
검증 순서① 인증된 GET/POST/PUT/DELETE ② 조직별 row ③ 실제 Oracle 컬럼 ④ 사진 파일 ⑤ BOM route activation 순서로 확인한다.
03위험·미구현·수락 기준

잔여 위험

  • BOM routeUI가 호출하는 /master/equip-bom/* controller/service/entity는 소스에 있으나 module에 등록되지 않았다. API 200 전에는 BOM CRUD를 구현 완료로 쓰지 않는다.
  • BOM auth/tenantcontroller guard 부재, service의 company/plant 인자와 entity organizationId 불일치가 있다.
  • 통신 저장commType은 body에 포함되지만 service가 무시하고, mqttTopic, serialPort, baudRate는 body에도 없다. 통신 필드는 현재 persistence path가 없다.
  • DBBOM table DDL/live existence가 이 source 대조 범위에서 증명되지 않았다.

완료 판정 체크

  • 적용공정 selector가 공정 코드·명·유형을 로드하고, filter와 save body의 processCode가 같은가.
  • 설비유형 선택지가 ISYS_BASECODE에서 로드되고 저장 code가 맞는가. grid는 코드명 renderer가 아니라 번역 fallback/원시 코드를 사용함을 확인했는가.
  • 기본 CRUD와 조직 격리, image MIME/5MB, 삭제 file/DB 결과를 확인했는가.
  • 통신 form-only 필드를 저장된 것으로 보고하지 않았는가.
  • BOM은 route 200·guard·tenant·DB relation을 모두 증명한 뒤에만 end-to-end 완료로 올리는가.
  • DTO/entity 길이 mismatch를 운영 schema에서 확인했는가.
