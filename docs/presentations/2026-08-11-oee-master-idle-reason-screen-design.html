02업무 규칙·코드 규칙
구분확정 동작화면·서버 주의
코드 키REASON_CODE + ORGANIZATION_ID로 저장한다. 수정 시 reasonCode disabled.신규 code는 입력 시 대문자화. 중복은 backend 409.
사유 구분PLAN/UNPLAN만 선택하며 화면에는 계획/비계획으로 표시한다.공통코드 조회가 아니라 page와 DTO의 소스 고정 enum이다.
OEE 반영Y/N를 반영/미반영으로 표시·저장한다.현재 화면은 factor/loss bucket을 입력하지 않는다.
표준시간비대상/대상 라디오. 대상일 때 수치와 HOUR/MIN/SEC 단위를 활성화한다.비대상 저장 payload의 stdTimeValue는 0.
매뉴얼사유코드가 입력된 뒤 businessType='설비비가동사유', refKey=reasonCode로 복수 첨부한다.편집 진입 시 기존 파일 GET 실패는 등록/수정을 막지 않는다.
저장reasonCode/name 필수 확인 후 POST 또는 PUT, 성공 시 목록 재조회.description/enum 범위·표시순서 음수 등은 현재 client save에서 깊게 검증하지 않는다.

03DB·계산·Acceptance·Mismatches
영역계약·처리검증·주의
사유 DBIP_EQUIP_DOWNTIME_REASON(REASON_CODE, ORGANIZATION_ID, REASON_NAME, DESCRIPTION, REASON_TYPE, OEE_REFLECT_YN, DISPLAY_ORDER, STD_TIME_YN/VALUE/UNIT, USE_YN, audit)entity 복합 primary key. list raw SQL에는 organization 1.
표시 계산stdTimeEnabled ? `${value} ${unitName(unit)}` : '비대상'계산 결과를 OEE에 반영하지 않음.
첨부 countFILE_ATTACHMENTS WHERE BUSINESS_TYPE='설비비가동사유' AND REF_KEY=REASON_CODE AND DEL_YN='N'수량만 목록에 표시; 실제 파일 metadata/list는 edit에서 조회
감사server fields는 userId 또는 default ADMIN, 날짜는 new Date/SYSDATE현재 auth user를 자동 주입하지 않음
확인 필요 · @Public/하드코드 조직IdleReasonController가 @Public()이고 Guard/조직 decorator가 없다. IdleReasonService는 const ORG = 1, 기본 사용자 ADMIN으로 조회·입력·수정·삭제한다. FILE_ATTACHMENTS 공통 route도 이 화면에서 인증 범위가 별도 확인되지 않는다.

Acceptance

  • 목록이 displayOrder/code 순으로 렌더된다.
  • 등록/수정 필수값과 enum 오류가 차단된다.
  • 대상/비대상 전환으로 입력 disabled가 바뀐다.
  • 편집 진입 시 기존 첨부 count/list가 맞다.
  • 저장 후 목록·manualCount가 갱신된다.
  • 파일 upload/download/delete가 refKey로 격리된다.

Mismatches

  • backend DELETE는 UI에 없음.
  • 고정 enum은 공통코드 기준정보 정책과 다름.
  • 첨부 component가 alert/confirm을 사용.
  • 저장 성공 후 첨부 변경을 master save와 원자화하지 않음.
  • 페이지/API 모두 multi-tenant/auth 계약이 없음.
