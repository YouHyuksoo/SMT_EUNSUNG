01요구사항과 사용자

목적

확인라인 코드·명·구분·제품구분·상태·용량·UPH·MES 표시·활성·설명을 IP_PRODUCT_LINE에 저장한다.

03업무 규칙·범위 경계
구분확인된 규칙화면 처리·주의
필수·자연키lineCode, lineName, lineDivision 필수. lineCode는 수정 불변, 조직 ID와 복합 PK.신규 버튼은 guard를 통과해야 열고 저장은 세 필드가 모두 있을 때만 활성.
초기값신규 기본 lineProductDivision=FIXED, lineStatus=N, mesDisplayYn=N, activeYn=N.activeYn N은 미사용이 아니라 “대기”다. useYn으로 해석하지 않는다.
코드·단위lineDivision, productDivision, status, capacityUom, activeYn은 shared enum/label을 사용한다. lineCodeGroup은 자유 입력.값·한글명은 shared constants 및 DB 주석 근거를 함께 검증한다.
수치capacity, uphValue, mesDisplaySequence는 숫자; DTO는 capacity/UPH/sequence ≥0.toPayload가 빈 문자열/null을 undefined로 바꾸어 Oracle 계약을 지킨다.
검색backend query는 code/name search, lineDivision/activeYn filter를 지원한다.현재 UI toolbar는 search 중심이며 enum filter는 DataGrid client column filter다.
삭제·상태삭제 confirm 후 lineCode로 DELETE. activeYn은 라인 가동 상태.구현 불일치controller/service 주석의 semantics와 실제 repository.delete가 hard delete인지 확인한다.

04수락 기준
  • header action 주입 후 새로고침·추가가 page 제목과 일관된다.
  • lineCode edit immutable, 필수값·enum·수치 검증이 API와 맞는다.
  • shared label이 grid·form·help에서 같은 값을 설명한다.
  • activeYn을 “사용여부”로 오표시하지 않고 활성/대기로 표시한다.
  • 저장 후 목록 재조회, 중복 409/validation 오류, dirty guard를 확인한다.
  • 실제 IP_PRODUCT_LINE 행과 organizationId·정렬순서를 대조한다.

명시해야 할 mismatch

구현 불일치DTO/backend는 lineDivision·activeYn 서버 필터를 지원하지만 toolbar는 search만 전송하고 enum은 DataGrid client filter에 의존한다.

구현 불일치screen field help는 코드성 설명을 제공하지만 lineCodeGroup은 ISYS_BASECODE가 아닌 자유 입력 컬럼이다.

구현 불일치삭제는 hard delete이며 공정/설비 참조 차단이 controller/service에 없다. 운영 삭제 정책을 확정한다.
