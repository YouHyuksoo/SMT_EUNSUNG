01목적·사용자·최신 변경 요지

목적

창고 코드·명칭·유형·공장·라인·공정을 관리하고, Location 탭에서 창고별 zone/row/col/level과 비고를 관리한다.

backend entity 원장은 ICOM_WAREHOUSE와 ICOM_WAREHOUSE_LOCATIONS; frontend help/SQL은 legacy WAREHOUSES 명칭을 남기고 있다.

직접 영향FLOOR 공정 field

WarehouseForm(FLOOR) → WarehouseFieldHelp.FieldProcessSelect → ProcessSelect 경로로만 공정 option을 읽는다.

원천은 GET /master/processes?limit=5000; value는 processCode, 기본 label은 코드 - 명칭, showProcessType은 false다.

사용자·탭

재고/자재 기준정보 담당자가 Warehouse 탭의 CRUD와 type/search, Location 탭의 parent filter/search/CRUD를 수행한다.

탭 전환 시 부모가 header의 refresh/add action을 교체한다. ProcessSelect는 FLOOR form이 mount될 때만 직접 호출된다.

04ProcessSelect 직접 영향과 간접 영향

직접 영향FLOOR form only

  • WarehouseForm이 FLOOR인 동안 FieldProcessSelect를 mount하고, shared selector가 /master/processes?limit=5000를 호출한다.
  • 선택값은 formData.processCode → POST/PUT /inventory/warehouses로 전달된다.
  • 공정 유형 표시는 이 화면에서 켜지지 않으며 option label 계약은 기존 code-name이다.

간접 영향조건·auth·legacy

  • FLOOR가 아니면 selector 자체가 렌더되지 않아 process master request도 발생하지 않는다.
  • warehouse controller의 auth 적용 여부와 process controller의 auth 적용 여부가 다르면 같은 화면에서 tab API와 selector API가 다른 실패 양상을 보일 수 있다.
  • frontend help/SQL의 WAREHOUSES overlay는 backend ICOM 원장과 별도이며, selector 전환과 schema mapping을 함께 검증해야 한다.

응답 shape

WarehouseController는 service object를 반환하고 global TransformInterceptor가 표준 {success,data,timestamp}로 감싼다. WarehouseList는 res.data.data가 array 또는 nested data인 양쪽을 해석한다.

LocationService는 자체적으로 {success:true,data:[]}를 반환하고 warehouseName을 join-like map으로 추가한다.

현재 위험type·field mapping

entity의 warehouseCode/name/type은 ICOM column인데 field help/sqlQuery는 WAREHOUSES/WAREHOUSE_LOCATIONS를 안내한다. 또한 form state의 plantCode는 API에 보낼 수 있지만 현재 form UI에는 입력 control이 없다.

문서는 어느 한쪽 schema를 새로 확정하지 않고 source mismatch를 acceptance blocker로 남긴다.

03인증·validation·DB

ProcessSelect·공정 master

  • ProcessController는 @UseGuards(JwtAuthGuard)를 명시하고 ProcessService.findAll에 organizationId를 전달한다.
  • ProcessSelect의 default contract는 value=processCode, label processCode - processName; processType은 rawData이며 현행 warehouse label에는 미표시다.
  • WAREHOUSE_TYPE_DTO_VALUES는 DTO @IsIn으로 RAW/WIP/FG/FLOOR/DEFECT/SCRAP/SUBCON만 허용한다.

Tenant·auth source

  • WarehouseController와 WarehouseLocationController는 @OrganizationId()를 받지만 클래스의 @UseGuards(JwtAuthGuard)가 현재 source에 없다.
  • WarehouseModule은 두 controller/service만 등록하고 guard module/provider를 등록하지 않는다. GuardModule은 AppModule import 근거가 없다.
  • 따라서 warehouse tab API와 guarded process option API의 인증/tenant 동작은 실제 HTTP로 확인하기 전 완료 처리하지 않는다.
04확인된 위험과 미결정
등급소스에서 확인된 내용완료 전 확인
HIGH · schemafrontend WarehouseFieldHelp와 DataGrid sqlQuery는 WAREHOUSES/WAREHOUSE_LOCATIONS, COMPANY='40'/PLANT_CD='1000'를 제시하지만 backend entity/service는 ICOM_WAREHOUSE/ICOM_WAREHOUSE_LOCATIONS/ORGANIZATION_ID를 사용한다.실제 개발/운영 Oracle의 공식 원장과 row/column을 대조하고 help/SQL 표시 계약을 결정.
HIGH · authwarehouse/location controller에는 @OrganizationId가 있으나 class-level @UseGuards(JwtAuthGuard)가 없다. 반면 ProcessController에는 guard가 있어 FLOOR selector 호출과 tab API가 다르게 동작할 수 있다.인증 없는 요청 및 organization undefined 처리의 실제 HTTP 결과를 확인. 코드 수정은 이 문서 범위 밖.
MEDIUM · typebackend entity response isDefault:string, frontend WarehouseData.isDefault:boolean, grid truthy rendering, DTO boolean→service Y/N 변환이 서로 다르다.Y/N ↔ boolean 변환과 기존 N row 표시를 API/render에서 검증.
MEDIUM · deleteservice 주석의 soft delete와 실제 warehouseRepository.delete/locationRepo.remove hard delete가 다르다. location delete에는 positive inventory 검사 source가 없다.FK/재고 참조 상태를 포함한 warehouse·location delete semantics를 실제 DB에서 확인.
MEDIUM · FLOORtype을 FLOOR에서 다른 값으로 바꿀 때 hidden lineCode/processCode를 form이 clear하지 않고 service는 전달된 값을 저장할 수 있다.FLOOR 전환 시 기존 값 보존/삭제 업무 규칙을 결정.
05수락 기준과 source evidence

재검증 시나리오

  • Warehouse/Location 탭 전환 시 목록 filter와 header action이 유지·교체된다.
  • warehouseType type filter, code/name search, FLOOR line/process 조건부 field가 현재 API와 일치한다.
  • FLOOR form의 process options는 실제 /master/processes?limit=5000의 현재 조직 rows이며 저장 key는 processCode다.
  • isDefault Y/N, location composite key, positive stock conflict, hard delete 결과를 인증된 API에서 확인한다.
  • ICOM_*와 legacy WAREHOUSES 표시가 실제 schema와 일치하는지, warehouse/location controller auth metadata를 결정한 뒤 완료한다.
