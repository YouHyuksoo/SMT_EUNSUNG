01요구사항 및 기능

목적

오늘의 핵심 운영 숫자를 빠르게 읽고 새로고침으로 최신 응답을 다시 요청한다. 본 문서는 /oee/dashboard가 아닌 전사형 /dashboard를 대상으로 한다.

사용자·표현

상단에 제목/부제와 새로고침 버튼을 두고, 4개 gradient 상태 카드와 3개 점검 요약 카드를 세로 스크롤 영역에 배치한다.

현재 페이지에는 날짜 선택, 차트, 카드 클릭 drill-down이 없다.

현재 기준선

현재 동작GET /dashboard/summary는 백엔드의 임시 mock을 받아 0건 요약을 표시한다. 화면은 이 값을 placeholder로 숨기지 않는다.

03비즈니스·구현 규칙
구분규칙/현재 사실화면 처리
요약 데이터equip, job, mat, defect, daily, periodic, pm 7개 섹션을 응답에서 읽는다.섹션이 있으면 해당 state만 교체한다. 누락 섹션은 기존 state를 유지한다.
날짜 기준프론트가 YYYY-MM-DD를 만들어 query로 보내지만 DashboardService.getSummary()의 현재 구현은 date/company/plant 인자를 사용하지 않는다.화면에 날짜 입력을 추가하거나 서버 날짜를 가정하지 않는다.
mock/placeholder백엔드 summary는 설비·작업·자재·불량·점검을 모두 0/빈 배열로 반환한다. 실제 PKG_DASHBOARD 프로시저 연결은 TODO다.0 값도 정상 응답으로 표시한다. “실데이터”라고 설명하지 않는다.
오류페이지 catch는 오류를 삼키고 현재 값을 유지한다. 초기값은 모두 0이다.로컬 오류 문구/재시도 버튼은 없고, 헤더 새로고침만 제공한다. Axios 전역 오류 모달 대상이면 전역 처리된다.
로딩loading과 inspectLoading을 동시에 켜고 finally에서 끈다.새로고침 아이콘 회전과 점검 카드 로딩 표현을 사용한다.

03DB·검증·수락 기준
영역현재 확인수락 기준
DB 경로summary는 Oracle 호출 없이 상수 mock 반환. KPI/최근생산만 PKG_DASHBOARD 호출 코드가 있다.현재 문서/화면에서 summary를 Oracle 실측값으로 오표기하지 않는다. 실데이터 전환 시 날짜·회사·사업장 전달을 별도 검증한다.
표시 정확성설비 4칸, 작업 4칸, 자재 4칸, 불량 4칸, 점검 3카드가 응답 키와 연결된다.응답 성공 시 각 키가 해당 카드에 표시되고, 점검 loading이 종료된다.
오류 재현summary fetch reject 시 catch가 현재 state를 보존하고 사용자 문구는 없다.초기 0 또는 직전 값이 사라지지 않으며 새로고침으로 재요청할 수 있다. 오류 가시화 개선은 별도 결정이다.
계약 mismatchgetSummary(_dateStr,_company,_plant)가 인자를 받지만 무시한다. 페이지가 KPI API를 사용하지 않는다.실데이터 설계 승인 전, summary 원천·업무일·tenant 범위를 확정한다.
접근성/반응형Tailwind grid와 하단 overflow 영역; 버튼 text와 icon이 함께 있다.좁은 화면에서 카드 1열, 긴 내용은 스크롤, 인쇄 시 A2 landscape 1 sheet/page로 렌더된다.
