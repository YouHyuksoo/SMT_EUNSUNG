3.2 입력·업무 validation

START

  • 온라인 + confirmed worker + SMT/ASSY 중 하나 이상 + resource 선택.
  • 모든 POST 후보는 status.state = RUNNING.
  • reasonCode 필수, memo는 500자 이하.
  • resource별 processCode/type/code/parentLineCode를 payload에 사용.

END

  • 온라인 + confirmed worker + 선택 resource.
  • 모든 POST 후보는 DOWNTIME이고 openEvent.eventId가 존재.
  • 각 resource의 eventId를 end payload에 사용.
  • 기존 danger ConfirmModal에서 count와 대상 확인 후 실행.

PRE-FLIGHT / STALE

  • 선택된 resource마다 command를 만들 수 있어야 한다.
  • 하나라도 status가 바뀌거나 필요한 event/reason이 없으면 POST 전에 refreshStatuses 후 중단.
  • 서버가 409를 반환하면 conflict로 보존하고 전체를 실패로 덮지 않는다.

IDEMPOTENCY

  • 같은 mode/resource/signature에는 pending requestId를 재사용.
  • 서버 replayed는 성공 완료로 표시.
  • 다른 requestId로 열린 이벤트가 경쟁하면 409를 오류가 아닌 재시도 가능한 conflict로 표시.

3.4 acceptance criteria TESTABLE
auth hydration 후 로그인 사용자가 자동 worker 후보가 되고, worker 확인 전 제출할 수 없다.

전체 공정은 SMT와 ASSY를 모두 선택/해제하고 각 process별 resource GET을 호출한다.
resource 전체 선택은 현재 mode에서 status-confirmed인 리소스만 대상으로 한다.

각 command payload의 processCode는 resource.processCode와 일치하고 ALL은 전송되지 않는다.
START/END는 RUNNING/DOWNTIME+openEvent 규칙을 지키며 stale 상태는 첫 POST 전에 중단한다.
partial result는 resource별로 보이고 success/replayed를 retry에서 제외한다.
START reason, memo 500자, offline, empty, unknown, 409 상태가 사용자에게 설명된다.
기존 6개 API·tenant/auth/idempotency contract와 ConfirmModal/네트워크 표시는 보존된다.
1280×800 desktop 및 10.1인치 Android 가로에서 사유·CTA·결과가 스크롤 없이 우선 보인다.
