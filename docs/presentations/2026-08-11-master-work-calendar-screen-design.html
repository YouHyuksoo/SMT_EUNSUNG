01요구사항 및 업무 경계

목적

연도·월·라인 기준으로 근무/휴무/반일/특근을 확인하고 일자별 근무분·잔업분·휴무사유를 저장한다.

라인 미지정은 전사 월력, 라인 지정은 예외 월력이다.

사용자·탭

생산계획·인사·기준정보 담당자. 월력관리와 교대시간 탭을 사용한다.

확정/확정취소·연간생성·전사복사는 확인 모달을 거친다.

핵심 결과

라인 예외가 있으면 source=LINE으로 표시하고, 확정일은 lock icon과 disabled cell로 표시한다.

근무분을 비우면 서버가 교대시간에서 자동 파생한다.

03DB·검증·완료 기준

DB / 서버 불변식

  • 전사 PK PLAN_DATE+ORGANIZATION_ID, 라인 PK PLAN_DATE+ORGANIZATION_ID+LINE_CODE.
  • line row가 company row를 같은 날짜에 override. 읽기 결과에만 source를 추가한다.
  • holidayYnOf(dayType)로 HOLIDAY_YN을 파생하고 DB check 정합을 지킨다.
  • 확정 범위에 Y가 있으면 delete+insert 쓰기를 transaction 안에서 재확인 후 거부한다.
  • 교대시간 DATESET~DATEEND overlap과 종료일<시작일은 409; 야간 cross-midnight는 허용.

수락 시나리오

  • 연도 입력 중 4자리 전에는 400 요청/중첩 모달이 발생하지 않는다.
  • 라인 선택 시 days와 summary가 같은 lineCode로 재조회되고 예외 badge가 보인다.
  • OFF 유형에서만 offReason을 보내며 dayType 변경 시 workMinutes auto draft로 돌아간다.
  • 확정 cell click/save/generate/copy가 차단되고 확정취소 후 다시 가능하다.
  • shift time 저장 후 순근무분과 월력 자동 근무분이 같은 규칙을 사용한다.
04현재 구현 불일치 및 백엔드 전용 동작

불일치화면·문서·계약

  • WorkCalendarFieldHelp.tsx의 주석은 WORK_CALENDARS / WORK_CALENDAR_DAYS / SHIFT_PATTERNS를 설명하지만 실제 entity/API 원장은 IP_PRODUCT_COMPANY_CALENDAR, IP_PRODUCT_LINE_CALENDAR, IP_SHIFT_TIME_MASTER다.
  • ConfirmDaysDto는 month(1~12)를 지원하지만 페이지는 year와 lineCode만 보내 연 전체를 확정/취소한다.
  • 달력의 요일 표기는 현재 Sun~Sat 영어이고, 업무 규칙/DB는 KST·한국 현장 기준이다.

백엔드 전용UI에 없는 동작

  • HOLIDAY_YN 파생, defaultWorkMinutes(), 감사 사용자/일시는 서버가 기록한다.
  • ShiftTimeService.resolveForDate()는 월력 서비스의 계산 지원 함수이며 별도 화면 action이 아니다.
  • generate/copy의 delete+insert transaction과 확정 재확인은 UI에서 보이지 않는 안전장치다.
  • 음력·대체공휴일을 자동 생성하는 endpoint는 없고, generate는 주말·양력 고정공휴일만 반영한다.
