검증 포인트현재 구현검증 증거·잔여 주의
대상 판정!machineCode || workstageGroup === 'PBA'일 때 실적/불량 액션을 노출한다.후공정 대상 외 행은 “대상 제외”; PBA 분류값이 실제 운영 코드와 맞는지 데이터 확인 필요.
실적 저장프론트는 설비 필수, resultQty >= 0을 확인한다. 서버 DTO는 정수·WIP/DONE을 확인하고 DONE 기존 row 수정은 거부한다.서버 DTO에 음수 금지 decorator가 없어 API 직접 호출의 음수 정합성은 별도 보강 대상.
DONEDB에서 읽은 savedStatus='DONE'만 수정불가. 신규 폼을 DONE으로 저장하는 것은 허용.“DONE 이후 수정불가”가 서비스와 화면에서 일치하는지 회귀 테스트.
대표불량badCode 필수, 계획수량 초과 금지, 실적합계가 양수면 실적수량 초과 금지. 저장은 실적과 독립.대표불량은 단일 row이며 실적별 detail 누적 모델과 다르다.
비가동설비·사유 필수, 시작은 서버 SYSDATE 기본, 이력의 종료 action은 endTime을 전송한다.백엔드의 MAX(DT_SEQ)+1와 시간 역전·중복 열린 행 검증은 서비스 계약으로 확인 필요.
실패 처리실적·대표불량은 서버 message 우선 toast, 비가동 시작·종료는 고정 실패 문구를 표시한다. 작업지시서 상세는 호출 경로가 없다.Oracle 원문 오류·재시도·부분 저장 여부를 API 통합 검증.

Acceptance

  • 조직이 다른 RUN_NO는 목록·상세·저장 모두 접근되지 않는다.
  • 3행 카드와 112px rail, 560px 세 panel 폭이 유지된다.
  • DONE 저장 row는 수정 필드와 저장 버튼이 잠긴다.
  • 대표불량은 한 작업지시 한 건이며 계획/실적 상한을 서버가 거부한다.
  • 동시 seq/dt 저장과 RUN_CARD write-back의 영향이 테스트로 재현된다.
  • work-result 저장 후 OEE 대시보드 미반영 경계를 안내한다.
