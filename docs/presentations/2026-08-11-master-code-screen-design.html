01요구사항과 사용자

목적

확인ISYS_BASECODE의 그룹·상세 코드 계약을 화면에서 관리한다. 그룹 선택 시 상세 목록을 읽고, 상세 코드의 명칭·설명·영문명·배지 속성을 편집한다.

실제 DB의 CODE_TYPE/CODE_NAME을 화면의 groupCode/detailCode로 매핑한다.

사용자·권한

추정시스템/기준정보 관리자. 실제 role name은 source에 없고 controller에는 JwtAuthGuard import가 있으나 local decorator 적용 여부는 확인이 필요하다.

핵심 결과

그룹 검색은 코드·번역·현재 언어 검색 텍스트를 모두 본다.

04수락 기준
  • 그룹 aggregate의 count·다국어 검색·첫 그룹 자동 선택이 실제 API와 일치한다.
  • 상세 composite key, codeName/description/English/attr1 저장과 preview가 동작한다.
  • sortOrder/useYn/parentCode가 실제 저장되는 것처럼 오해를 만들지 않는다.
  • 코드 라벨을 참조하는 화면을 확인한 뒤 삭제·명칭 변경을 수행한다.
  • 409 duplicate, 404 missing, validation 오류에서 group/detail context를 유지한다.
  • controller guard/tenant metadata를 확인하고 조직 밖 코드가 섞이지 않는다.

명시해야 할 mismatch

구현 불일치ISYS_BASECODE entity에는 parentCode/sortOrder/useYn/attr2/attr3가 실컬럼이 아니며 service는 parent=null/sort=0/use=Y를 virtual로 반환한다.

구현 불일치form은 sortOrder/useYn을 입력하지만 service create/update가 이를 저장하지 않는다. UI를 계약으로 확정하지 않는다.

구현 불일치ComCodeController는 JwtAuthGuard를 import하지만 소스에 @UseGuards 적용이 보이지 않는다. 전역 guard인지 명시 검증이 필요하다.
