01요구사항 및 사용자 흐름

목적

품목과 공정에 적용되는 문서를 목록으로 탐색하고, 이미지/PDF/문서 첨부와 작업 순서 본문을 제공한다.

행 클릭은 preview, edit icon/preview의 수정은 edit panel이다.

식별자

작업지도서는 itemCode + processCode + revision 복합키로 식별한다.

수정 시 세 키는 disabled이고 title/content/image/use 값만 변경한다.

결과

LIST DataGrid / PREVIEW 520px 읽기 panel / EDIT 480px panel / 삭제 확인.

상세 preview는 content 포함 단건을 재조회한다.

03DB·검증·완료 기준

DB / 서버 불변식

  • WORK_INSTRUCTIONS PK는 itemCode·processCode·revision·organizationId. 생성 시 동일 키를 409로 거부한다.
  • title 200/255자, processCode 50자, revision 10자, imageUrl 500자 등 DTO/엔티티 길이를 지킨다.
  • upload는 확장자와 MIME를 함께 검사하고 10MB를 넘으면 거부한다.
  • 서버 update는 key columns를 변경하지 않고 title/content/imageUrl/useYn만 patch한다.

수락 시나리오

  • 검색 결과에서 행 click → preview detail, 이미지/PDF/기타 파일 renderer가 각각 동작한다.
  • 신규 필수 누락·중복 복합키·지원하지 않는 파일·10MB 초과는 저장하지 않는다.
  • 첨부 upload 성공 후 URL이 payload에 들어가고, preview에서 새 탭/다운로드가 가능하다.
  • 편집 중 행 전환/닫기는 dirty confirm, 저장 성공 후 목록과 패널이 동기화된다.
  • 삭제 확인 후 목록에서 제거되고 복합키를 잘못 encode하면 404/오류로 남는다.
04현재 구현 불일치 및 백엔드 전용 동작

불일치본문 보존 위험

  • WorkInstructionPreviewPanel은 detail content를 조회하지만, 수정 전환 시 WorkInstructionFormPanel.buildForm()은 content:""으로 초기화한다.
  • 현재 edit PUT은 form 전체를 보내므로, 기존 본문을 읽지 않고 수정 저장하면 CONTENT가 빈 문자열로 덮일 수 있다. 설계는 이 동작을 숨기지 않고 회귀 검증 대상으로 남긴다.
  • backend DTO/entity에는 useYn이 있으나 현재 edit form에는 Y/N control이 없고 grid의 점 표시만 있다.

백엔드 전용현재 UI에서 직접 제공하지 않는 기능

  • itemCode, processCode, useYn query filter는 API DTO에 있으나 page filter는 search 하나다.
  • 생성/수정 DTO의 useYn patch는 가능하지만 화면에서는 조작할 수 없다.
  • 파일 업로드는 저장된 URL만 남기고 기존 파일을 삭제하는 별도 endpoint가 없다. URL 제거는 DB 값만 비운다.
  • organizationId·created/updated audit 값은 server decorator/entity가 채운다.
