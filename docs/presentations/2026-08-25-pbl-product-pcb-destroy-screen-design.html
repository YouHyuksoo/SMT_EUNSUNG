PCB Serial No를 기준으로 폐기 대상 IP_PRODUCT_WORK_QC row를 조회한다. 대상이 없으면 신규 폐기 QC row를 등록하고, 선택 row를 Issue 또는 Issue Cancel하여 RECEIPT_DEFICIT와 REPAIR_DATE를 바꾼다.

DW_1 / DW_2

Destroy / register path

  • PID modified 시 dw_1.retrieve(serial, org)로 기존 row를 찾고, 이미 있으면 신규 등록하지 않는다.
  • row가 없으면 IP_PRODUCT_2D_BARCODE에서 item/model을 조회한 뒤 f_insert() → dw_1.InsertRow()로 값을 구성한다.
  • f_update() → DW_1.UPDATE()가 SRD의 update table IP_PRODUCT_WORK_QC에 등록하며, Batch Destroy는 staging row마다 같은 PID event를 호출한다.

History / Issue path

  • History는 line/workstage/model/serial/QC date 범위와 조직을 bind한다.
  • Issue는 선택한 QC_SEQUENCE + SERIAL_NO + ORG로 RECEIPT_DEFICIT='2'와 REPAIR_DATE=sysdate를 update한다.
  • Issue Cancel은 별도 where 조건을 사용하므로 Page 3 위험을 함께 본다.

수락 기준

  • Destroy / History 라디오와 세 DW 전환, 필터 bind, staging Paste/Reset/Save As가 rendered PB 화면과 일치한다.
  • Issue는 QC_SEQUENCE·SERIAL_NO·ORG 한 row만 변경하고 commit 후 두 목록이 재조회된다.
  • Issue Cancel의 다중 sequence 위험을 재현하고, 보완 전에는 제한/경고를 표시한다.
  • Bad reason 선택, 신규 row insert, WQC/LQC code label을 실제 DB column까지 추적한다.
  • batch status는 실제 SQL 실패와 일치하거나 staging-only로 명확히 표시한다.
  • History 종료일·최종 공정 org 조건·empty/error를 실SQL로 검증한다.
