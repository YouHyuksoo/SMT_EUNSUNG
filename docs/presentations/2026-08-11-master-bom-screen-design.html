01요구사항 및 사용자

목적

제품/반제품 부모를 찾고 현재 기준일의 BOM 계층을 펼쳐 자재 구성과 투입 공정을 한 화면에서 확인한다.

선택한 BOM 행은 라우팅 및 공정별 투입자재 패널과 연결된다.

주 사용자

생산기술·자재 기준정보 담당자. 부모 선택, 자식 추가/수정/삭제, Excel preview/upload, export를 수행한다.

품목은 PartSelect/GET /master/parts 검색으로 선택한다.

기준일 모드

기준일 오늘 기본값으로 유효 BOM만 조회 / 전체이력 날짜 조건 없이 조회.

hierarchy는 화면에서 depth 10을 요청하고 서버도 최대 10으로 제한한다.

03DB·검증·완료 기준

DB / 서버 불변식

  • 엔티티 ID_ENG_BOM는 모·자·DATESET·조직 복합 PK, DATEEND·소요량·순서·공정·LINE_TYPE 등을 저장한다.
  • 기준일 hierarchy는 Oracle CONNECT BY, depth는 1~10으로 clamp한다.
  • 신규/수정의 동일 모·자·적용일자 중복은 Conflict. 날짜 key는 로컬 자정으로 정규화한다.
  • Excel 실제 업로드는 품목 존재, 필수값, parent=child, DB/파일 중복을 행별 검증하고 신규만 INSERT한다.

수락 시나리오

  • 기준일 변경 시 부모와 트리가 같은 날짜 기준으로 재조회된다.
  • 부모 선택 후 root가 표시되고 expand/collapse 및 child row 선택이 동작한다.
  • CRUD 성공 후 트리 갱신; 중복·잘못된 날짜는 입력과 오류 맥락을 보존한다.
  • Excel preview에서 중복이 있으면 upload가 차단되고, 완료 건수/오류 행이 표시된다.
  • 라우팅 패널은 품목 선택·공정 선택·투입자재 저장까지 선택 context를 잃지 않는다.
04현재 구현 불일치 및 백엔드 전용 동작

불일치UI와 실제 원장

  • frontend type/form의 bomGrp, ecoNo, useYn은 DTO에는 있으나 BomMaster의 실제 decorated column이 아니다. 현재 엔티티는 화면 호환 필드로만 선언하고, side는 실제 LINE_TYPE에 매핑된다.
  • findParents()의 SQL은 revisions를 NULL로 반환하고, hierarchy의 processName도 NULL이다. UI는 “-” 또는 processCode fallback을 사용한다.
  • 서비스는 생성 시 useYn:'Y'를 보내지만 실제 저장 컬럼 계약은 별도 확인 대상이다.

백엔드 전용현재 page가 직접 사용하지 않는 route

  • GET /master/boms: pagination BOM flat 목록.
  • GET /master/boms/parent/{parentItemCode}: 부모 직속 행 목록.
  • GET /master/boms/{id}: 단건 조회. UI CRUD 후 응답 내부에서 서비스가 사용한다.
  • 라우팅 legacy /master/routings는 이 화면의 nested routing-group 계약과 별도이므로 혼용하지 않는다.
