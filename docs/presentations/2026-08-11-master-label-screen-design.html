01요구사항 및 정보 흐름

목적

라벨 source table을 선택하고 text/barcode/shape/image 객체를 캔버스에 배치해 위치·크기·표현을 저장한다.

실제 데이터 대신 source field의 sample을 preview에 사용한다.

사용자·카테고리

기준정보/현장 출력 담당자. 현재 UI category는 equip, jig, worker, mat_lot, box, pallet, sg, fg다.

진입·source 전환 시 category별 기본 또는 default 템플릿을 자동 로드한다.

핵심 결과

DESIGN JSON / TEMPLATE CRUD / PREVIEW sample renderer / IMAGE upload.

저장 성공 시 dirty baseline을 현재 JSON으로 갱신한다.

03DB·검증·완료 기준

DB / server rule

  • ICOM_LABEL_TEMPLATES PK는 templateName+category+organizationId. 같은 category의 templateName 중복은 Conflict.
  • designData와 zplCode는 CLOB, printMode는 BROWSER/ZPL/BOTH, category는 DTO enum.
  • isDefault 생성/수정 시 같은 조직·category의 기존 default를 false로 만든다.
  • image upload는 확장자/MIME 이미지와 5MB를 검증하고 저장 파일 URL만 JSON에 넣는다.

수락 시나리오

  • category 진입 시 default 우선/최근 fallback이 canvas와 template list를 동기화한다.
  • 객체 추가·이동·resize·property 수정·duplicate/delete가 JSON과 preview에 함께 반영된다.
  • source field를 바꾸면 sample value와 renderer 결과가 바뀌고 bounds 밖 좌표가 저장되지 않는다.
  • dirty 상태에서 다른 template load/new를 누르면 discard confirmation; 저장/overwrite 후 dirty 해제.
  • 동일 templateName/category 저장은 오류, 삭제는 확인 후 목록에서 제거된다.
04현재 구현 불일치 및 백엔드 전용 동작

불일치category·실데이터·출력

  • backend LABEL_TEMPLATE_CATEGORIES에는 part가 있지만 frontend LabelCategory/sourceCategoryMap과 source definitions에는 part가 없다.
  • canvas/preview는 labelSources.ts의 고정 sample data를 사용한다. 실제 설비·LOT·BOX·PALLET 조회 또는 인쇄 실행은 page에 연결되어 있지 않다.
  • LabelDesign의 legacy top-level barcode/codeText/nameText/subText와 version 2 elements가 함께 존재하지만 renderer의 실제 객체 표현은 elements 중심이다.

백엔드 전용DTO/entity에만 있는 action/field

  • remark, isDefault, zplCode, printMode, printerId, useYn 입력·편집 control이 현재 UI에 없다. star는 API가 준 isDefault 표시만 한다.
  • GET 단건 route와 서버의 clearDefaultByCategory는 hook/page에서 직접 action으로 노출되지 않는다.
  • LabelPrintRenderer는 컴포넌트에 존재하지만 현재 page는 인쇄 버튼/프린터 API를 호출하지 않는다.
  • 출력 mode(ZPL/BROWSER/BOTH)와 실제 프린터 선택은 별도 승인 후에만 화면 범위를 확장한다.
