01요구사항 및 기능

목적·흐름

좌측에 카테고리→메뉴 트리를 표시하고, 카테고리/leaf 선택에 따라 우측 패널을 바꾼다. 미배치 메뉴는 tray에서 카테고리로 즉시 배치한다.

관리 규칙

카테고리는 영문 대문자/숫자/underscore 2–50자, __ROOT__는 예약어다. 한 tenant의 leaf는 하나의 카테고리에만 배치된다.

초기화·화이트리스트

tree GET 때 누락된 기본 layout을 transaction으로 seed하고, menuConfig.ts의 known leaf만 트리/미배치 목록에 포함한다.

03비즈니스·구현 규칙
구분규칙/현재 사실화면 처리
카테고리 생성code/labelKey/iconName 입력. 신규 sortOrder는 service가 9999, active는 Y로 저장한다.“카테고리 추가” 후 new-category panel; 생성 성공 refresh.
루트 보호__ROOT__는 생성/삭제 불가, label/icon/active 변경 불가; sortOrder만 수정 가능하다.root panel에서 label/icon/active disabled, delete 숨김.
정렬카테고리와 동일 카테고리 메뉴는 DnD 후 (index+1)*10으로 일괄 갱신한다. 메뉴 이동/tray 배치는 sortOrder 9999.drag end 후 즉시 PATCH → onChange refresh.
삭제자식 메뉴가 있으면 409; 빈 카테고리만 삭제. 현재 프론트는 별도 confirm modal이 없다.패널 delete button; 실패는 패널 error text로 표시.
오류·dirtypage refresh와 일부 panel fetch는 local catch/dirty guard가 없다.전역 Axios 오류 처리에 의존하고, 저장 전 이탈 확인은 현재 범위에 존재하지 않는다.

03DB·검증·수락 기준
영역현재 확인수락 기준
인증·tenant두 controller에 클래스 @UseGuards(JwtAuthGuard); req.user.organizationId 없으면 BadRequest.비인증/조직 없는 요청 차단, 모든 CRUD/reorder가 organizationId와 audit user를 사용한다.
코드 validationDTO regex/길이, service root/중복, item whitelist/category 존재를 검사한다.알 수 없는 leaf, root 생성·삭제, 중복 category를 저장하지 않는다.
삭제 안전category child count > 0이면 409, root는 400. 프론트는 삭제 confirm이 없다.백엔드 차단을 유지하고, 확인 modal 도입은 별도 UX 승인 후에 한다.
정렬·무결성reorder는 transaction, item PK는 tenant+menuCode, category FK는 tenant+categoryCode.DnD 후 순서·소속이 재조회 결과에 일치하고, 한 leaf가 두 category에 중복되지 않는다.
오류·dirty페이지 초기 refresh/일부 list fetch에 local error/dirty guard 없음.현재 전역 오류 의존을 문서화하고, 별도 개선 전에는 동작을 새로 가정하지 않는다.
