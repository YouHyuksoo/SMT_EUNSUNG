01요구사항 및 기능

작업 관리

검색/그룹/실행유형 필터, 작업 등록·수정, 활성 toggle, 즉시실행, 삭제를 제공한다. ADMIN만 mutation action을 본다.

실행 이력

기본 최근 7일~오늘, 작업/상태 필터, 실행시간·처리건수·재시도 목록. FAIL/TIMEOUT 행만 상세 modal을 연다.

대시보드 현재 mismatch

중요프론트는 trend/jobStats를 읽지만 backend summary는 dailyTrend/jobRatio를 반환한다. 카드 숫자는 보일 수 있어도 두 차트는 비어 있을 수 있다.

03비즈니스·보안 규칙
구분규칙/현재 사실화면 처리
작업 권한Job controller는 JwtAuthGuard+RolesGuard; POST/PUT/DELETE/run/toggle는 ADMIN. 로그 controller는 인증 사용자 조회 가능.프론트도 user.role==='ADMIN'일 때 등록/수정/삭제/즉시실행을 표시한다.
실행 유형SERVICE/PROCEDURE/SQL/HTTP/SCRIPT. service whitelist, SQL은 SELECT/DELETE 시작 + 위험 keyword 차단, HTTP host/script path allowlist가 있다.execType별 동적 form; JSON headers/body는 저장 전 parse한다.
Cron/활성생성은 backend가 isActive N. toggle Y면 CronJob 등록/nextRun, N이면 해제/nextRun null. 서버 시작 시 활성 job 재등록.Y/N toggle은 ADMIN만 클릭 가능. cron 설명은 cronstrue ko.
실행 로그RUNNING 생성, 성공/실패/TIMEOUT 등 갱신; stale RUNNING/RETRYING은 재시작 시 FAIL 복구.FAIL/TIMEOUT만 LogDetailModal을 열고 errorMsg를 pre로 표시한다.
오류 은닉job/log/dashboard fetch는 empty 배열/EMPTY로 대체. toggle/modal 저장 catch는 API interceptor에 맡긴다. job option fetch는 ignore.조회 실패가 “데이터 없음”처럼 보일 수 있는 현재 동작을 기록한다.

03DB·검증·수락 기준
영역현재 확인수락 기준
조직·권한job/log query는 organizationId, mutations는 ADMIN RolesGuard. executor의 tenant-aware service/SQL binding 테스트가 있다.다른 조직 job/log 접근·실행 금지, viewer mutation 차단, SQL/HTTP/script allowlist 유지.
입력 validationjobCode 대문자 pattern, execType enum, cron/target 길이, retry 0–10, timeout 10–3600. 프론트 INIT timeout은 60, backend default는 300이다.신규/수정 payload와 실행기 계약을 검증하고 timeout default mismatch를 결정한다.
summarytoday cards는 key가 일치하지만 dailyTrend/jobRatio와 frontend trend/jobStats가 다르다. backend jobRatio에는 total도 있다.현재 baseline에서는 cards/최근 실패와 빈 차트를 구분해 표시한다. key adapter 없이는 차트 정상으로 판정하지 않는다.
오류job/log/dashboard fetch 실패는 empty/EMPTY, modal/toggle catch는 API interceptor 의존.실패 후 화면이 멈추지 않고 refresh 가능하되, 빈 목록 오인 위험을 residual risk로 남긴다.
로그LOG_ID는 Oracle sequence query, stale RUNNING/RETRYING는 FAIL 복구.실행 시작/종료·duration·retry·error를 확인하고 서버 재시작 복구를 재현한다.
