01목적·사용자·최신 변경 요지

목적

부모 품목 목록과 재귀 BOM 트리를 기준일 또는 전체이력으로 조회한다. 트리의 선택 행을 라우팅 관리와 공정별 투입자재 패널의 context로 넘긴다.

root는 화면이 만든 synthetic row이며 실제 ID_ENG_BOM CRUD 대상이 아니다.

직접 영향공정코드 입력

BomFormModal → BomFieldHelp.FieldProcessSelect → ProcessSelect 경로가 공정 옵션을 읽는다.

현재 원천은 장비 metadata가 아니라 GET /master/processes?limit=5000; 값은 processCode, 기본 라벨은 코드 - 명칭이다.

주 사용자·범위

생산기술·자재 기준정보 담당자가 부모 검색, 다단 BOM CRUD, 선택 행 routing 조회, 투입자재 편집, template/preview/upload/export를 수행한다.

showProcessType은 이 화면에서 전달하지 않으므로 유형 라벨은 표시하지 않는다.

04ProcessSelect 직접 영향과 간접 영향

직접 영향모달 공정 필드

  • 추가·수정 모달이 열릴 때 shared selector가 /master/processes?limit=5000를 조회한다.
  • 선택값은 BOM row의 processCode → ID_ENG_BOM.WORKSTAGE_CODE 계약으로 전달된다.
  • 기존 equipment metadata endpoint의 옵션·응답 shape를 더 이상 사용하지 않는다.

간접 영향routing/material context

  • 트리 row의 routing 버튼은 별도로 /master/routing-groups를 검색하고 선택 그룹의 processes를 조회한다. 이 nested 목록은 ProcessSelect를 다시 렌더하지 않는다.
  • BOM page는 nested process의 seq를 읽지만 backend routing entity/service는 processSeq를 반환하며 alias mapper가 없다. 같은 응답 mismatch가 routing blueprint의 blocker다.
  • 그룹 process의 표시명은 API가 workstageName을 주지 않으면 frontend가 workstageCode로 fallback한다.
  • 공정마스터에 없는 기존 코드가 options에 없으면 selector의 current value 보존 fallback이 없으므로 별도 데이터 정합성 확인이 필요하다.

원장과 호환 필드

BomMaster의 실제 decorated column은 PARENT_ITEM_CODE, CHILD_ITEM_CODE, DATESET, ORGANIZATION_ID, DATEEND, ITEM_UNIT_QTY, SORT_SEQUENCE, WORKSTAGE_CODE, LINE_TYPE 등이다.

bomGrp, ecoNo, useYn, side는 entity의 “화면 호환용 비저장 필드”다. service update만 side → lineType으로 매핑한다.

현재 위험create와 실제 column

create/upload service는 DTO의 side를 entity create에 넣지만 실제 저장 column은 lineType이다. 현재 소스만으로 create 시 side가 원장에 저장된다고 보장할 수 없다.

문서는 이 차이를 새 호환 계약으로 확정하지 않고, DB/CRUD 확인 항목으로 남긴다.

03인증·validation·tenant

공정 옵션 경계

  • ProcessController는 클래스에 @UseGuards(JwtAuthGuard)가 있고 @OrganizationId()를 service로 전달한다.
  • ProcessMaster 자연키는 WORKSTAGE_CODE + ORGANIZATION_ID; options는 현재 조직의 IP_PRODUCT_WORKSTAGE rows다.
  • ProcessSelect는 default false에서 code - name을 유지하고, showProcessType=true일 때만 WORKSTAGE TYPE codeName을 붙인다. BOM은 false다.

서버 validation

  • BOM DTO: parent/child string, qty ≥ 0, seq 정수 ≥ 0, 날짜 ISO, 길이 제한. service: parent≠child, 같은 모·자·적용일자 Conflict, 날짜를 서버 로컬 자정으로 정규화.
  • Excel은 품목 존재와 행별 필수·중복을 추가 확인한다. hierarchy와 parents는 조직 조건을 SQL에 넣는다.
  • BOM service에는 ProcessMaster repository/ref check가 없다. selector에서 고른 code라도 저장 시 BOM 공정 FK/존재 재검증이 현재 코드에 없다.
04현재 위험과 미결정
등급소스에서 확인된 내용완료 전 확인
HIGH · authBomController는 @OrganizationId()를 사용하지만 클래스에 @UseGuards(JwtAuthGuard)가 없다. MasterBomModule도 guard module/provider를 등록하지 않는다. GuardModule은 존재하지만 AppModule import 근거가 없다.인증 없는 요청·조직 undefined가 실제 HTTP에서 거부되는지 확인하고, 필요한 guard 결정은 coordinator가 소유한다. 이 문서는 코드를 고치지 않는다.
MEDIUM · optionProcessSelect는 현재 value를 options에 주입하는 fallback이 없다. legacy BOM row의 WORKSTAGE_CODE가 tenant 공정마스터 응답에 없으면 모달 표시와 수정값 복원이 불완전할 수 있다.조직별 IP_PRODUCT_WORKSTAGE와 ID_ENG_BOM.WORKSTAGE_CODE 교집합을 실제 데이터로 확인.
HIGH · nested seqBOM page의 nested routing panel은 process response에서 seq를 읽지만 current routing entity/service는 processSeq를 반환하고 alias mapper가 없다.선택 BOM row → routing process → material editor path의 실제 HTTP response property를 검증.
MEDIUM · DB map실제 entity는 LINE_TYPE을 side 원장으로 두지만 create/upload body는 비저장 호환 side를 사용한다. bomGrp/ecoNo/useYn도 entity decorated column이 아니다.Oracle CRUD 후 create/update/export round-trip을 확인하고 공식 column mapping을 결정.
BACKEND-ONLYGET /master/boms, parent/{parentItemCode}, {id}는 controller/service에 있으나 현재 page가 직접 호출하지 않는다.화면 계약과 backend-only route를 혼합하지 않는다.
05수락 기준과 source evidence

재검증 시나리오

  • 기준일 변경은 parents와 tree에 같은 날짜를 반영하고, 전체이력은 date 없이 조회한다.
  • 부모 선택 → root → child row → routing group/process → material editor context가 유지된다.
  • BOM form의 공정 option은 /master/processes?limit=5000의 현재 조직 rows에서 오고 저장 value는 processCode다.
  • 중복 모·자·적용일자, parent=child, Excel duplicate/error가 UI와 API에서 구분된다.
  • side/호환 필드와 BOM controller auth를 실제 API/DB에 대조한 뒤 완료한다.
