02업무 규칙 및 화면 규칙
구분확정 동작화면 표현·예외
일자날짜 입력은 YYYY-MM-DD, 최대값은 브라우저의 오늘이다.미래 선택은 UI에서 차단되지만 백엔드 isLive(workDate >= today)는 미래도 실시간으로 분류한다.
데이터 계층당일 이상은 V_OEE_LIVE, 과거는 OEE_DAILY_SUMMARY에서 읽는다.과거 조회 행이 0건이면 폴백 없이 409를 “집계 미생성(마감 필요)”으로 변환한다.
카드공정별 OEE 대형 수치와 가동·성능·양품·UPH·계획달성·생산수량을 표시한다.OEE ≥ 85% 초록, ≥ 60% 황색, 그 미만 적색. SMT만 PICKUP_RATE를 추가 표시한다.
보조 KPIOEE_MATERIAL_READINESS의 공정별 준비율과 OEE_CUSTOMER_DEFECT 합계 반입량을 표시한다.행이 없으면 준비율은 “-”, 고객불량은 0. OEE에 곱하지 않는다.
조회 실패409 이외 네트워크·500 오류는 공통 API 오류 처리로 전달한다.로딩·빈 결과·오류 메시지를 구분하며 성공 전환이나 임의 0값으로 대체하지 않는다.
이동전체 “리소스 드릴다운”과 각 공정 “리소스별 보기”가 processCode/date를 전달한다.이 화면에서 로스 파레토·수정·마감·생산입력은 수행하지 않는다.

04수락 기준·소스·불일치

Acceptance

  • 오늘 일자 200이면 live pill과 공정 rows를 표시한다.
  • 과거 snapshot 존재 시 snapshot pill을 표시한다.
  • 과거 409는 오류 모달이 아니라 마감 필요 안내다.
  • SMT에만 픽업율을 노출한다.
  • 공정 링크가 동일 date/process를 전달한다.

검증 커맨드

  • pnpm --filter @eunsung/frontend typecheck
  • 대시보드 페이지 렌더 확인
  • 인증 HTTP 200 및 409 fixture 확인
  • Oracle live/snapshot 행·순서 대조

실 DB 화면은 컴파일만으로 완료 처리하지 않는다.

Mismatches

  • frontend 날짜는 브라우저 local, backend는 KST.
  • UI max today와 backend future-live 규칙이 다름.
  • 계획 문서의 display 44/45/46과 현재 authenticated route가 다름.
  • 실제 카드는 차트가 아닌 텍스트 카드.
