# 현장 작업자용 '설비 운영 및 실적관리'

작성일: 2026-09-09

## 목적

현장 작업자가 한 화면에서 **비가동 처리**와 **작업실적 등록**만 하도록 만든 앱.
관리자용 `설비 운영 현황`(비가동 처리 탭)을 바탕으로 신규 개발한다.

## 메뉴

| 항목 | 값 |
|---|---|
| 메뉴명 | 설비 운영 및 실적관리 |
| 코드 | `OEE_FIELD_OPS` |
| 경로 | `/oee/field-ops` |
| 위치 | OEE관리 **맨 뒤** |

맨 뒤에 붙이는 이유: `menu-config.json`의 배열 순서가 sortOrder다. 앞에 끼우면 기존
메뉴가 밀려 원격 팀 테스트가 깨진다(2026-09-01 `OEE_OVERALL_STATUS`에서 겪음).

## 화면 구성

기존 3분할을 유지한다. 탭은 없다.

```
┌────────┬──────────────────┬────────────────────┐
│ 당일   │ 비가동 대상 설비   │ 작업실적 관리       │
│ 지표   │      [이력보기]    │  [당일자▼] [조회]   │
│        │ 원인│설비│유형│상태│ 작업지시 그리드      │
│ 가동율 │  ☑ │ES-1│ … │가동│  (2줄, 스크롤)      │
│ 파이   │                   │ ─────────────────  │
│ 막대   │  [비가동 전환]     │  [작업 실적 등록]    │
└────────┴──────────────────┴────────────────────┘
```

상단: 라인/설비 선택 + 바코드 + **작업자 콤보**(신규)

### 기존 대비 변경

| 구분 | 처리 |
|---|---|
| 자동갱신·상단 조회 | **삭제** (동작 후 자동 재조회는 유지) |
| 탭(모니터링/비가동 처리) | **삭제** — 단일 화면 |
| 작업자 콤보 | **신규** — 바코드 입력폼 우측 |
| 이전 30일 목록 | 중앙 '비가동 대상 설비' 옆 **[이력보기] 팝업**으로 이동 |
| 우측 영역 | '작업실적 관리'로 교체 |
| 원인설비 체크 · 당일 지표 | **유지** |

### 작업지시 그리드 (2줄)

```
1행 : 작업지시번호 · 계획일 · 교대조
2행 : 품번 | 리비전 · 품명
```

행 선택 표시는 `설비별 작업 실적관리` 목록 방식을 따른다.
하단 고정 **[작업 실적 등록]** 버튼은 좌측 '비가동 전환' 버튼과 같은 크기.

## 결정사항

| 항목 | 결정 | 근거 |
|---|---|---|
| 작업자 저장 | 비가동 `WORKER`=**사번**, 실적 `WORKER_NAME`=**이름** | 컬럼 의미에 맞춤. 실적 팝업 기본값으로 넣고 수정 가능 |
| 목록 기간 | '작업실적 관리' 타이틀 우측 **날짜 1개(기본 당일) + 조회 버튼** | 상단 조회는 없애되 이 영역만 자체 조회 |
| 실적 등록 폼 | **공용 컴포넌트로 추출** | 기존은 슬라이드 패널, 신규는 Modal로 감싼다. 산식·저장 로직을 한 곳에 둔다 |
| 품명 | `ID_ITEM.ITEM_NAME` 추가 | RunRow에 품명이 없었다. `MODEL_NAME`과 다른 값이다 |
| 설비 필터 | 백엔드 `list()`에 `machineCode` 파라미터 추가 | 지금은 `keyword`가 품번·모델명에도 걸려 엉뚱한 지시가 섞인다 |

## 알려진 제약

**`WORKER_MASTERS`가 0건이다.** 작업자 콤보가 비어 있게 된다. 작업자관리에서
등록해야 쓸 수 있다. (2026-09-09 스키마 보정으로 등록 자체는 가능해졌다.)
