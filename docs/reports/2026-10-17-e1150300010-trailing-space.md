# 품목코드 끝 공백 정리 (2026-10-17, ESDBext)

자재장기재고리포트에서 `E1150300010`(HALL SENSOR) 재고 6행의 구매단가·재고금액이 비어 있었다.
재고 행 품목코드가 `'E1150300010 '`(끝 공백)이라 공백 없는 코드로 등록된 구매단가(265원)와 맞지 않았다.
조회 SQL은 인덱스를 그대로 쓰도록 두고 데이터를 고쳤다. 이어서 사용자 지시("공백이 있는건 전부 공백 제거")로
끝 공백 품목코드 9개 전부의 현재 데이터를 공백 없는 코드로 옮겼다.

대상 9개: `E0440300020` `E0440300030` `E1150300010` `E1160100020` `E1160300060` `E1160300070` `E2921100040` `M1590-117700B` `M30420019843`
(`ID_ITEM.ITEM_CODE <> TRIM(ITEM_CODE)` 전부).

## 1차 — E1150300010

| 테이블 | 행 |
|---|---|
| `IM_ITEM_INVENTORY` | 20 |
| `IM_ITEM_RECEIPT_BARCODE` | 23 |
| `IM_ITEM_INVENTORY_CLOSE` (2026-09, F, M01) | 1 |

복구: `docs/sql/e1150300010-trailing-space-rollback-2026-10-17.sql`

## 2차 — 9개 전부 (현재 데이터)

품목 하나당 한 트랜잭션, 사전 행 수와 영향 행 수가 같을 때만 커밋했다. 드라이런 후 적용.

| 테이블.컬럼 | 행 | 방법 |
|---|---|---|
| `IM_ITEM_INVENTORY.ITEM_CODE` | 5,651 | 이름 변경. 롯트+창고 고유 인덱스라 겹침 없음 |
| `IM_ITEM_RECEIPT_BARCODE.ITEM_CODE` | 5,759 | 이름 변경 |
| `IM_ITEM_BAKING_MASTER.ITEM_CODE` | 25 | 이름 변경 |
| `ID_ENG_BOM.PARENT/CHILD_ITEM_CODE` | 18 / 16 | 이름 변경. 34행 모두 현재 유효 BOM, 키 겹침 없음 |
| `ID_ENG_BOM_TEMP.PARENT/CHILD_ITEM_CODE` | 3,565 / 1,978 | 이름 변경 |
| `ID_ITEM.PART_NO` | 10 | 값의 공백 제거 |
| `IM_ITEM_INVENTORY_GEN` | 5 | 3 이름 변경, 2 합산(공백 없는 행에 수량 더하고 공백 행 삭제) |
| `IM_ITEM_WORKSTAGE_INVENTORY` | 5 | 3 이름 변경, 2 합산(둘 다 수량 0) |
| `ID_ITEM` 신규 | 3 | `E1160100020` `M1590-117700B` `M30420019843` 은 공백 없는 마스터가 없어 공백 행을 복사해 등록 |

- 신규 마스터 3개는 `TRG_ID_ITEM_INS` 가 구매품목(`IM_ITEM_MASTER`)·구매단가(`IM_ITEM_UNIT_PRICE`, 단가 0) 기본행을 1개씩 만들었다(품목 등록과 같은 동작). 세 품목 재고는 모두 수량 0이다.
- 사후: 위 표에서 공백 코드 0행. `IM_ITEM_INVENTORY` 전체에서 끝 공백 코드 0행.
- 복구: `docs/sql/item-code-trailing-space-rollback-2026-10-17.sql` (품목별 역순, ROWID 기준)

## 3차 — 마감 원장·이력 + 공백 품목 마스터 삭제

사용자 확인: 현재 마감은 테스트용 임시 마감이라 바꿔도 된다. 마감 잠금 트리거 4개
(`TRG_IM_ITEM_ISSUE_LOCK` `TRG_IM_ITEM_RECEIPT_LOCK` `TRG_IM_WS_RECEIPT_LOCK` `TRG_IM_WS_ISSUE_LOCK`)를 끄고 적용한 뒤
다시 켰다(사후 VALID·ENABLED). 품목코드만 바꿔 재고를 움직이는 수정 트리거(`UPDATE OF last_modify_date/receipt_qty/issue_qty/issue_status`)는 돌지 않았다.

|---|---|
| `IM_ITEM_ISSUE` | 9,844 |
| `IM_ITEM_RECEIPT` | 3,653 |
| `IM_ITEM_WORKSTAGE_RECEIPT` | 4,983 |
| `IM_ITEM_WORKSTAGE_ISSUE` | 2,235 |
| `IM_ITEM_RECEIPT_SLIP` | 268 |
| `IM_ITEM_ISSUE_LOSS` | 2 |
| `IM_ITEM_WORKSTAGE_INV_CLOSE` | 2 (키 겹침 없음) |
| `IP_PRODUCT_PCB_SCAN_MASTER` | 4,998 |
| `IP_PRODUCT_RUN_CARD_DETAIL` | 114 |
| `IM_ITEM_PURCHASE_REQUIR_ORDER.PARENT_ITEM_CODE` | 14 |

- 사후: 위 표와 `ID_ITEM` 에 공백 코드 0행.
- 시간 제한 없이 따로 센 큰 표 `IP_PRODUCT_2D_BARCODE`(ITEM_CODE·PART_NO·MODEL_SUFFIX), `IQ_MACHINE_INSPECT_DATA_SPI.MODEL_CODE`,
  `IQ_MACHINE_INSPECT_SMNT1/2.MODEL_SUFFIX`, `ID_ITEM_HISTORY.PART_NO` 는 공백 코드 0행.
- `ID_ITEM_HISTORY.ITEM_CODE` 9행은 삭제된 공백 품목 마스터의 변경 이력이라 그대로 둔다.
