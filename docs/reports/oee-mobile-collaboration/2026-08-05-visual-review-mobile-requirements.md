## 1. 읽기 기준과 범위

이 문서는 시각 검토서에서 모바일·PDA·현장 스캔으로 직접 확인되는 요구사항과, 모바일 후보로 확장할 수 있는 현장 업무를 분리해 추출한다. 원문은 `DRAFT FOR CUSTOMER DECISION`, `고객 합의 전 검토용` 상태이므로 모든 항목은 Master 합의 전까지 승인된 계약으로 취급하지 않는다 (`visual-review.html:378-413`).

요청한 1~5 그룹은 다음 **5단계 계층**으로 해석했다.

| 레벨 | 의미 |
|---|---|
| Group 1 | 시스템/제품 영역 |
| Group 2 | 업무 도메인 |
| Group 3 | 업무 기능군 |
| Group 4 | 사용자 흐름 또는 시나리오 |
| Group 5 | **단위기능** — 하나의 입력/행동/판정/출력으로 검증 가능한 최소 기능 |

단위기능 판정 기준은 `행위자 1명 + 트리거 1개 + 결과 1개 + 검증조건 1개`다.

## 2. 상태 태그

| 태그 | 의미 |
|---|---|
| `M-확정후보` | 원문이 PDA/현장 입력으로 직접 명시한 모바일 후보 |
| `M-현장후보` | 스캔·현장 거래 흐름은 명확하지만 모바일 화면이라고 직접 확정하지 않은 후보 |
| `T-태블릿후보` | 조회·모니터링·관리자 업무. 모바일로 확대하려면 별도 승인 필요 |
| `P-선행조건` | 모바일 화면이 동작하기 전에 기준정보/API/권한으로 준비해야 하는 항목 |
| `D-결정필요` | 원문이 초안 또는 협의 항목으로 남긴 내용 |
| `O-제외` | PC·관리자·마감 등 현재 모바일 범위에서 제외할 항목 |

## 5. 문서에서 직접 확인되는 Mobile 범위와 제외 범위

### 5.1 상세 설계 1차 대상 후보

1. **M1 `/oee/equip-downtime-mobile`** — 원문의 PDA OEE 입력 시나리오와 직접 대응한다. 현재 저장/API·사유코드·권한 계약은 미확정이다.
2. **M2 현장 수불 스캔** — 원자재·반제품·완제품의 스캔 단위와 거래 규칙은 명확하지만, 현재 OEE Mobile 화면과 별도 업무 범위다. Master의 추가 승인이 필요하다.
3. **M3 실사 스캔** — 현장 스캔 후보지만 조정 거래·확정 권한까지 포함하면 별도 업무 기능으로 분리해야 한다.

### 5.2 현재 상세 설계에서 제외

- OEE Dashboard/모니터링: 문서상 벽면·PC·순회 관리자 용도이며 작업자 PDA와 사용 목적이 다르다.
- OEE 마감 실행·스냅샷 확정: 관리자 권한과 오류 해소 정책이 필요하다.
- 기준정보 관리: 모바일 작업자의 입력 기능이 아니라 선행 관리 기능이다.
- 재고 조회 8관점: 현재 문서의 조회 Mock은 관리자 조회 중심이며 모바일 요구로 확정되지 않았다.
- ERP 인터페이스: 원문도 이번 단계에서 후속 과제로 제외한다 (`visual-review.html:412-413, 624-630`).

## 6. 요구사항→설계 전환 게이트

`luna_planner`는 아래 항목을 확인하기 전 상세 화면설계를 시작하지 않는다.

1. Master가 M1/M2/M3 중 설계 대상 ID를 명시적으로 승인한다.
2. 각 대상의 행위자·입력·출력·상태·실패·빈 상태가 확정된다.
3. PC와 Mobile의 책임 경계가 확정된다.
4. 스캔 단위와 원장 기록 단위가 확정된다.
5. OEE 사유코드와 통제·손실·귀속지표가 승인된다.
6. 기준정보 누락 시 차단/경고/마감오류 중 처리 방식이 정해진다.
7. API/DB 계약, 권한, 서버시각, 중복요청, 오프라인 정책의 소유자가 정해진다.
8. 화면별 테스트 가능한 acceptance criteria를 Master가 승인한다.

## 7. 현재 결정 대기

- **최우선:** M1만 설계할지, M2 현장 수불 스캔과 M3 실사 스캔을 함께 설계할지
- OEE PDA의 사유코드 최종 목록과 `통제구분 × 손실유형 × 귀속지표` 매핑
- 반제품 전수 인수·부분 인수 금지의 예외 처리 권한
- 바코드 없는 완제품의 UID 생성 및 파일럿 승인
- 모바일 저장 API와 서버 권한·시각·중복 처리 계약
- 모바일에서 조회/마감 기능을 제공할지, PC/관리자 화면으로 고정할지

**Phase 상태:** 요구사항 추출 완료. 상세 화면설계는 Master의 대상 확정 전까지 보류한다.
