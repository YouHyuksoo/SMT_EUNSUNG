# OEE 라인 출처 정정 결과

- 작성일: 2026-08-13
- 작성 계기: 확정 OEE 라인 범위를 SMT 01~12, 조립 19~24로 재확인
- 대상 DB: `EUNSUNG_DEV_ESDBPDB`, schema `INFINITY21_JSMES`

## 요약 (결론 먼저)

- OEE 리소스를 SMT `01~12`, 조립 `19~24`로 정정했다.
- OEE가 조립 CELL로 해석했던 `50~64`는 OEE에서 제외했다.
- `PLANTS`에 복제했던 OEE 전용 18행은 모두 삭제했다.
- 원천 `IP_PRODUCT_LINE`은 삭제하거나 수정하지 않았다.

## 상세

### 데이터 출처

- `50~61`: `IP_PRODUCT_LINE`에 2021-04-15부터 존재, `ENTER_BY='ADMIN'`
- `62~64`: 2022-06-10부터 존재, `ENTER_BY='LJH'`
- 따라서 `50~64`는 OEE가 원천 라인마스터에 추가한 데이터가 아니다.
- 2026-08-07 OEE 재평가 문서가 `LINE_DIVISION='L'`인 50~64를 2층 CELL 후보로 선택했고 이후 `PLANTS`와 `OEE_RESOURCE`에 복제했다. 이 해석이 현재 확정 범위와 달랐다.
- `19~20`은 2019년 기존 라인이다.
- `21~24`는 `ENTER_BY='CODEX'`, `ENTER_DATE='2026-08-12 22:54:16'`이다. 저장소에는 생성 SQL이나 Git 이력이 남아 있지 않아 정확한 실행 세션은 특정할 수 없지만 자동화 작업에서 추가된 데이터로 판단된다. 사용자가 현재 확정 마스터라고 명시했으므로 유지했다.

### 정리 결과

- `PLANTS` OEE 계층: 18건 → 0건
- OEE 파생 ASSY CELL 50~64: 15건 → 0건
- OEE 검증 이벤트 22: 정확한 이벤트 ID와 request ID를 확인한 뒤 삭제
- 현재 `OEE_DOWNTIME_EVENT`: 0건
- 현재 OEE 리소스:
  - SMT LINE 01~12: 12건
  - ASSY LINE 19~24: 6건

### 보존 데이터

- `IP_PRODUCT_LINE` 50~64는 기존 원천 마스터이므로 삭제하지 않았다.
- 다른 `PLANTS` 데이터와 회사·사업장 기능은 변경하지 않았다.

## 후속 조치

- 21~24의 생성 감사 주체가 `CODEX`인 점은 별도 운영 감사가 필요하면 Oracle audit/접속 로그로 확인한다.
- OEE는 앞으로 확정 코드 목록 01~12와 19~24만 사용한다.
