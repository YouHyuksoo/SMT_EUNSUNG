# 공정관리 그리드 경계·스크롤 보정 설계

## 목표

공정관리의 상·하단 카드 우측 테두리를 온전히 표시하고, 두 DataGrid를 카드 내부에 고정해 가로·세로 스크롤이 내부에서 동작하도록 한다. 하단 헤더 간격과 그리드 여백을 상단 기준에 맞추고 설비배치 버튼을 항상 노출한다.

## 확인된 원인

- 두 카드와 콘텐츠 래퍼가 넓은 테이블에 대한 너비 경계를 명시하지 않아 우측 외곽선이 잘릴 수 있다.
- 하단 `CardContent`에는 상단과 같은 `px-4 py-3`이 없어 그리드가 카드 외곽선에 붙는다.
- DataGrid 자체는 `overflow-auto`이지만 부모의 `min-w-0`·`min-h-0` 경계가 일관되지 않아 카드 내부 스크롤 영역이 안정적으로 제한되지 않는다.
- 건수를 제목에 합친 뒤 제목 영역에 `min-w-0`이 없고 설비배치 버튼에도 `flex-shrink-0`이 없어 버튼이 우측으로 밀릴 수 있다.

## 카드와 그리드

- 상단 `ProcessList`와 하단 `ProcessEquipGrid` 카드에 `w-full max-w-full overflow-hidden`을 적용한다.
- 두 `CardContent`를 `flex-1 min-w-0 min-h-0 overflow-hidden px-4 py-3`으로 통일한다.
- DataGrid 공용 컴포넌트의 기존 `overflow-auto`를 그대로 사용해 가로·세로 스크롤을 제공한다.
- 공용 `Card`와 `DataGrid` 구현은 변경하지 않는다.
- 상하 60:40 비율은 유지한다. 여기서 “같은 크기”는 두 그리드의 카드 내부 좌우·상하 inset이 동일하다는 의미이며 높이를 50:50으로 바꾸지 않는다.

## 하단 헤더와 설비배치 버튼

- 하단 헤더 패딩을 `px-4 pt-3 pb-1`로 바꿔 구분선을 제목에 더 가깝게 배치한다.
- 헤더 행은 가운데 정렬을 유지하며 제목 컨테이너에 `flex-1 min-w-0`을 적용한다.
- 제목은 필요한 경우 줄바꿈할 수 있게 하고 건수는 공정 정보 뒤에 유지한다.
- 설비배치 버튼 래퍼 또는 버튼에 `flex-shrink-0`을 적용해 항상 카드 안에 표시한다.

## 데이터·동작

공정 선택, 설비 조회, 설비 배치·해제, 공정 CRUD, API 및 DB 계약은 변경하지 않는다. 등록·수정 패널과 설비 배치 모달 구성도 유지한다.

## 검증

- 구조 테스트에서 두 카드의 `w-full max-w-full overflow-hidden`을 확인한다.
- 두 CardContent의 `min-w-0 min-h-0 overflow-hidden px-4 py-3` 일치를 확인한다.
- 하단 헤더의 `px-4 pt-3 pb-1`, 제목의 `flex-1 min-w-0`, 설비배치 버튼의 수축 방지 연결을 확인한다.
- 기존 60:40 배치, 인라인 건수, 등록 패널·설비 배치 모달 테스트를 유지한다.
- focused 테스트, 전체 프론트 테스트, typecheck를 실행한다.
- 사용자가 기동한 dev 서버가 있으면 우측 테두리, 양방향 내부 스크롤, 헤더 구분선, 설비배치 버튼을 실제 화면에서 확인한다.

## 비범위

- 공용 Card/DataGrid 변경
- 60:40 높이 비율 또는 컬럼 구성 변경
- API·DB·등록 팝업 변경
