# 공정 재공 이동 설계 (재공수불)

- 작성일: 2026-11-05
- 상태: 구현·ESDB 적용 완료
- 관련: `docs/specs/2026-11-05-routing-by-code-design.md`, `docs/specs/2026-10-17-wip-semi-product-from-aoi-design.md` 5-7

## 1. 결정

사용자 지시(2026-11-05): 실적이 발생하면 그 공정에 재공이 생기고, 다음 공정에서 실적이 발생하면 이전 공정의 재공이 줄어든다. ICT 는 검사 공정이라
자재 소모는 없지만 사용자가 그 공정의 재공을 보고 싶어 한다. 공정 순서는 라우팅(`ID_ITEM.ROUTING_CODE` → `IP_ROUTING_PROCESSES`)이 정한다.

- 포장이 아닌 공정 실적(DONE): 그 실적 품목의 **반제품 재공**을 이전 공정에서 빼고 이 공정에 넣는다(`P_ROUTING_RESULT_WIP`).
- 자재 차감은 하지 않는다. 소모는 지금처럼 포장 완제품 실적에서 BOM 으로 한다(`P_PRODUCT_RESULT_WIP`).
- 반제품 실적(AOI·수기·보정)의 BOM 차감(`P_ASSY_RESULT_ADD`)도 그대로다.

## 2. 동작

| 항목 | 규칙 |
|---|---|
| 이동 대상 | `P_PRODUCT_RESULT_WIP` 와 같은 반제품 판정(AOI 생산 반제품, 원자재만 제품은 제품 자신) × BOM 소요량 × 실적수량 |
| 출발 공정 | 라우팅에서 이 공정 바로 앞 공정. 첫 공정이면 반제품이 지금 있는 공정(후공정 우선, 수량 많은 곳, 없으면 W180). 출발 = 도착이면 건너뜀 |
| 기록 | 출발 공정 출고 + 도착 공정 입고 한 쌍, `ENTER_BY='WS_MOVE'`(`P_WIP_MOVE_BY_MAGAZINE` 과 같은 표시), `LAST_MODIFY_BY='RW:<일자>:<순번>'`(실적 키) |
| 합계 | 한 쌍이라 품목 합계 0. 재고 합계·마감·원장·인팩 전송 장부(`WS_MOVE` 제외, 출고는 `INV ADJUST` 만 반응)에 영향 없음. 공정별 수량은 `IM_ITEM_WORKSTAGE_INV_WS` |
| 중복 | 같은 실적 키 입고 행의 순합계가 0 이 아니면 SKIP |
| 취소 | 그 실적 키 행을 같은 수량 음수로 넣어 옮긴 만큼만 되돌린다 |
| 제외 | 포장(P)·수리(R) 실적, 전환(`WIP_RESULT_CONSUME_FROM`) 전 실적, 수량 0, 라우팅 없는 품목, 실적 공정이 라우팅에 없음, 제외 모델 |
| 반영여부 | 옮겼으면 `WORKSTAGE_ISSUE_YN='Y'`(취소 `C`), 아니면 `X` 그대로. 실패는 실적을 남기고 경고, 표시는 덮지 않는다 |

## 3. 주의

- 라우팅 마지막 공정(대부분 W205)에 재공이 쌓이고, 포장 BOM 차감이 반제품이 있는 공정(후공정 우선, 수량 많은 곳)에서 뺀다.
- 중간 공정 실적을 입력하지 않으면 그 공정 재공이 건너뛰어진다(이전 공정에서 바로 빠지지 않고 다음 공정 실적 때 이전 공정에서 뺀다).
- 소스: `oracle_db_scripts/P_ROUTING_RESULT_WIP.sql`, 앱 `work-result.service.ts`(`applyRouting`).
