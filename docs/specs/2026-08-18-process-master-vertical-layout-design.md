# 공정관리 메인 화면 상하 배치 설계

## 목표

공정관리 메인 화면의 공정마스터 그리드와 배치된 설비 그리드를 기존 좌우 배치에서 상하 배치로 변경한다. 공정마스터는 상단 60%, 배치된 설비는 하단 40%를 사용한다.

## 범위

- `ProcessList`를 본문 상단에 배치한다.
- `ProcessEquipGrid`를 본문 하단에 배치한다.
- 본문은 `3fr 2fr` 비율의 CSS Grid 행 구조를 사용한다.
- 공정 선택에 따른 설비 조회, 공정 및 설비 CRUD, 새로고침, 엑셀 업로드 동작은 변경하지 않는다.
- 공정 등록·수정 슬라이드 패널, 설비 배치 모달, 삭제 확인 모달의 구성과 동작은 유지한다.
- 좌우 배치를 설명하는 소스 주석과 사용자 도움말을 상하 배치 기준으로 갱신한다.

## 구현 방식

현재 두 그리드를 감싸는 12열 CSS Grid와 `col-span-7`, `col-span-5`를 제거하고, 같은 위치에 `grid-rows-[minmax(0,3fr)_minmax(0,2fr)]` 형태의 2행 Grid를 적용한다. 각 그리드 래퍼는 `min-h-0`을 유지해 내부 데이터 그리드의 스크롤 영역이 화면 높이를 넘지 않게 한다.

등록·수정 슬라이드 패널은 두 그리드의 바깥 형제 요소로 유지한다. 패널이 열릴 때 상하 배치 영역의 가로폭만 줄어들고, 패널 자체 너비와 내부 필드 구성은 변하지 않는다.

## 검증

- 구조 테스트에서 본문이 3:2 행 비율을 사용하고 기존 12열/7:5 좌우 배치 클래스가 제거됐는지 확인한다.
- 구조 테스트에서 공정 등록·수정 패널 및 설비 배치 모달의 기존 연결이 유지되는지 확인한다.
- 프론트엔드 focused test와 typecheck를 실행한다.
- 실행 중인 사용자 dev 서버가 있으면 실제 공정관리 화면에서 상하 60:40 배치, 내부 스크롤, 공정 선택 시 설비 목록 갱신, 등록 팝업 구성을 확인한다.

## 비범위

- 두 영역의 높이를 사용자가 드래그해 조절하는 기능
- 그리드 컬럼, 조회 API, DB 스키마 또는 데이터 계약 변경
- 등록·수정 및 설비 배치 팝업의 디자인 변경
