# 생산라인 OEE 속성 통합 설계

## 목적

생산라인관리에서 OEE 라인 관리의 핵심 분류 정보인 작업장, OEE유형, 상위라인코드를 함께 관리한다. 데이터는 `IP_PRODUCT_LINE`에 직접 저장하며, 기존 `OEE_RESOURCE` 데이터와 기능은 이번 작업에서 변경하지 않는다.

## 현재 동작

- 생산라인관리는 `IP_PRODUCT_LINE`을 기준으로 라인코드, 라인명, 제품구분, 라인상태 등을 관리한다.
- OEE 라인 관리는 별도 메뉴와 `OEE_RESOURCE` 기반 화면에서 작업장과 OEE유형을 관리한다.
- 생산라인 등록·수정 폼과 목록에는 작업장, OEE유형, 상위라인코드가 없다.
- OEE 라인 관리 메뉴가 현재 노출되어 있다.

## 승인된 설계

### 데이터 모델

`IP_PRODUCT_LINE`에 다음 nullable 컬럼을 추가한다. 기존 행은 데이터 보정 없이 `NULL`을 허용하여 호환성을 유지한다.

| DB 컬럼 | 애플리케이션 필드 | 형식 | 값 |
|---|---|---|---|
| `PROCESS_CODE` | `processCode` | `VARCHAR2(20)` | `SMT`, `ASSY` |
| `RESOURCE_TYPE` | `resourceType` | `VARCHAR2(20)` | `LINE`, `CELL` |
| `PARENT_LINE_CODE` | `parentLineCode` | `VARCHAR2(20)` | 생산라인 코드 |

- 신규 등록 기본값은 작업장 `SMT`, OEE유형 `LINE`이다.
- OEE유형이 `LINE`이면 상위라인코드는 자신의 라인코드로 자동 설정한다.
- OEE유형이 `CELL`이면 같은 조직의 다른 생산라인 중 하나를 상위라인으로 반드시 선택한다. 현재 편집 중인 라인은 후보에서 제외한다.
- 백엔드는 프론트 입력에 의존하지 않고 동일 규칙을 검증한다.
- `PROCESS_CODE`와 `RESOURCE_TYPE`에는 `NULL`을 허용하면서 정의된 코드만 받는 체크 제약조건을 적용한다.
- 상위라인의 존재 여부와 같은 조직 여부는 서비스 계층에서 검증한다. 이번 범위에서는 별도 외래키를 추가하지 않는다.

### 생산라인 등록·수정 화면

- 기존 공용 선택 컴포넌트와 폼 스타일을 재사용한다.
- `제품구분`, `라인상태` 행 바로 아래에 다음 순서로 배치한다.
  1. 작업장: `SMT`, `ASSY` 콤보박스
  2. OEE유형: `LINE`, `CELL` 콤보박스
  3. 상위라인코드: 생산라인 콤보박스
- 상위라인코드는 항상 콤보박스로 표시한다.
- `LINE` 선택 시 자신의 라인코드를 표시하고 변경할 수 없게 한다.
- `CELL` 선택 시 동일 조직의 생산라인 목록에서 현재 라인을 제외하고 선택할 수 있게 한다.
- 라인코드 또는 OEE유형 변경 시 상위라인 값을 즉시 해당 규칙에 맞게 재계산한다.

### 생산라인 목록

- `제품구분`, `라인상태` 열 다음에 작업장, OEE유형, 상위라인코드 열을 같은 순서로 추가한다.
- 작업장과 OEE유형은 코드값이 아니라 사용자가 이해할 수 있는 코드명을 표시한다.
- 기존 검색, 정렬, 엑셀 내보내기 동작에 새 열을 포함한다.

### 백엔드 계약

- 생산라인 엔티티, 생성·수정 DTO, 조회 응답, 서비스 SQL에 세 필드를 실제 DB 컬럼명과 대응하는 lowerCamelCase로 추가한다.
- 등록과 수정 모두 OEE유형별 상위라인 규칙을 검증한다.
- `CELL`의 상위라인이 없거나, 자기 자신이거나, 같은 조직에 존재하지 않으면 저장을 거부한다.
- `LINE`은 요청값과 관계없이 상위라인코드를 자신의 라인코드로 정규화한다.
- `OEE_RESOURCE` 조회·등록·수정·삭제 및 OEE 실적/가동 기능은 변경하지 않는다.

### 메뉴

- 프론트 메뉴 설정과 백엔드 메뉴 시드에서 `OEE_MST_RESOURCE` 항목을 숨긴다.
- `/oee/master/resource` 페이지와 관련 API·소스는 삭제하지 않아 직접 URL 접근과 추후 정리 여지를 유지한다.

### 다국어

- 생산라인관리의 작업장, OEE유형, 상위라인코드 라벨과 선택 항목을 한국어·영어·베트남어·중국어 리소스에 추가한다.
- 기존 OEE 화면의 번역 키를 재사용할 수 있으면 재사용하고, 생산라인 전용 문구만 새로 추가한다.

## 적용 순서

1. 운영 Oracle에서 `IP_PRODUCT_LINE`의 실제 컬럼과 제약조건을 조회한다.
2. 세 컬럼과 체크 제약조건을 실제 DB에 적용하고 사후 스키마를 확인한다.
3. 백엔드 엔티티·DTO·서비스 및 테스트를 변경한다.
4. 프론트 폼·목록·다국어·메뉴 설정 및 구조 테스트를 변경한다.
5. 백엔드 메뉴 시드에서 메뉴를 숨기고 등록 검증을 수행한다.

## 검증

- DB: 적용 전후 컬럼·제약조건을 조회하고, 허용 코드 및 nullable 기존 행 호환성을 확인한다.
- 백엔드: 조회 결과 매핑, 신규 기본값, `LINE` 자기 참조 정규화, `CELL` 정상 상위라인, 누락·자기참조·타 조직/미존재 라인 거부를 테스트한다.
- 프론트: 폼 배치 순서, 세 콤보 구성, 유형 전환 동작, 그리드 열 순서와 코드명 표시를 구조 테스트로 확인한다.
- 메뉴: 프론트 메뉴와 백엔드 메뉴 등록 정보에서 OEE 라인 관리가 노출되지 않는지 확인한다.
- 타입/회귀: 프론트 typecheck·test와 백엔드 관련 Jest·TypeScript 검사를 실행한다.
- 개발 서버가 이미 실행 중인 경우에만 인증된 API와 실제 렌더링을 확인한다. 서버는 에이전트가 임의 기동하지 않는다.

## 제외 범위

- `OEE_RESOURCE` 데이터 이관, 동기화 또는 스키마 변경
- OEE 실적·가동 기능의 참조 테이블 변경
- OEE 라인 관리 페이지와 API 소스 삭제
- 기존 생산라인 행에 대한 작업장·OEE유형·상위라인 데이터 일괄 보정
