# 다중입력 종료 사유 유지 및 변경

## 사용자 승인

- 종료 대상의 기존 사유가 모두 같으면 사유 선택 창과 같은 형식(사유명 / 사유구분 · 사유코드)으로 표시하고 오른쪽에 작업자변경과 유사한 별도 `사유변경` 버튼을 둔다.
- 서로 다른 사유라도 미입력이 없으면 각 실적의 기존 사유를 유지한 채 일괄 종료할 수 있다.
- 일부만 미입력이면 `미입력 사유 포함`, 모두 미입력이면 `사유 선택`으로 표시하고 공통 최종 사유 선택 전에는 종료할 수 없다.
- 사용자가 사유변경으로 사유를 선택한 경우에만 전체 종료 대상에 해당 사유를 덮어쓴다.
- 종료 대상을 바꾸면 새 대상 기준으로 다시 판정하며 이전 선택 대상에 대한 사유 override를 이어서 적용하지 않는다.
- 동일 시각·전체 성공/전체 취소·복수 미종료·설비 라인 대체·통신 결과 확인 흐름은 유지한다.

## Coordinator 계약

- 기존 POST `/oee/multi-entry/end` body의 reasonCode를 optional로 변경한다. 생략은 기존 사유 유지, 유효 nonempty 문자열은 전체 적용이다. 빈 문자열/null/비문자열은 변경 사유로 허용하지 않는다.
- 유지 경로는 실제 모든 종료 대상을 잠금·집합 비교한 후 모든 REASON_CODE가 nonblank인지 검사한다. 하나라도 미입력이면 DML 전에 전체 거부한다. 기존 코드의 활성 여부는 유지 경로에서 재선택 조건으로 강제하지 않는다.
- 유지 UPDATE는 REASON_CODE를 SET하지 않는다. 변경 경로만 활성 사유 검증 후 REASON_CODE를 SET한다. 두 SQL 모두 실제 Oracle positional bind 순서·numeric affected count와 공통 종료 시각 기준을 지킨다.
- 프론트는 기존 사유의 자동 요약과 사용자의 명시적 변경 선택을 분리한다. 동일 기존 사유를 화면에 표시해도 요청 reasonCode는 생략한다.
- 명시적 변경이 없으면 응답 검증은 모든 종료 이벤트의 사유가 nonblank인지 확인한다. 명시적 변경이면 모든 이벤트 reasonCode가 선택값과 같은지 확인한다. 기존 시각·조직·대상 집합 검증 유지.
- 대상/실적 스냅샷 key로 override를 한정하여 선택 변경이나 상태 변경 후 이전 override가 남지 않게 한다.
- 기존 reasons API의 코드/이름/구분을 재사용한다. 실제 현재 미종료10건은 QC01(품질 확인 대기, UNPLAN, 활성)8건 및 EB01(설비 고장, UNPLAN, 활성)2건으로 이름/구분 조회 가능함을 확인했다. 코드 정보가 없는 경우 이름을 추측하지 않고 정보 미확인 표시를 제공한다.
- 모든 입력에 사유가 있는 유지 경로는 선택용 사유 목록을 불러오지 못했다고 막지 않는다. 새 사유 선택 경로의 유효성 검사는 기존대로 유지한다.
- 같은 사유 / 서로 다른 사유 / 일부 미입력 / 모두 미입력의 문구와 표시를 4개 locale에 반영한다. START의 사유 선택 입력은 유지한다.

## 완료 기준

- backend: 생략 유지(서로 다른 사유 포함), 변경 overwrite, null/blank 입력 거부, 잠금 후 미입력 발견 시 전부 실패·DML없음, 실제 driver 반환·bind 회귀 검증.
- frontend: 네 가지 요약 상태, 동일 사유의 이름/구분/코드, 명시적 선택과 자동표시 분리, 선택 변경 후 override 초기화, 유지 payload의 reasonCode 생략, 응답 검증.
- 격리된 시스템 Chrome + 모의 API로 유지·변경·미입력 차단·요약/버튼 배치를 확인한다. 실제 Oracle에서는 신규 테스트 행만 이용해 유지/변경을 검증하고 rollback한다.
- 기존 업무 실적은 검증을 위해 종료하지 않는다. 인증 API/렌더 경계 미확인 사항은 결과에 기록한다.
