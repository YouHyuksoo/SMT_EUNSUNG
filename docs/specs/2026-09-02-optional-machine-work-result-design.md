# 설비별 작업 실적 설비 선택사항 변경 설계

## 목적

OEE 관리의 `설비별 작업 실적관리` 실적 등록 화면에서 설비를 선택하지 않아도 실적을 저장할 수 있게 한다. 설비 선택 여부와 관계없이 작업지시의 공정 정보는 유지한다.

## 현재 동작

- 실적 등록 화면이 설비선택에 필수 표시(`*`)를 노출한다.
- 프론트엔드 `saveResult`가 설비코드가 없으면 저장을 중단한다.
- 백엔드 `WorkResultUpsertDto`가 `machineCode`를 필수 문자열로 검증한다.
- 저장 대상인 `IP_PRODUCT_SENSOR_ACTUAL.MACHINE_CODE`와 대응 엔티티 필드는 이미 `NULL`을 허용한다.
- 신규 실적 폼은 작업지시의 기존 `WORKSTAGE_CODE`를 기본값으로 가진다.

## 승인된 설계

### 프론트엔드

- 설비선택 라벨의 필수 표시를 제거한다.
- 설비 미선택 저장 차단 검증을 제거한다.
- 미선택 상태에서는 `machineCode`를 빈 문자열이 아닌 선택값 부재로 API에 전달한다.
- 설비를 선택하면 현재처럼 해당 설비의 설비코드와 공정코드를 폼에 반영한다.
- 실적수량 등 기존 필수 검증과 완료 실적 수정 제한은 유지한다.

### 백엔드

- `WorkResultUpsertDto.machineCode`를 선택 문자열로 변경한다.
- 서비스는 값이 없거나 빈 문자열이면 `null`로 정규화하여 `IP_PRODUCT_SENSOR_ACTUAL.MACHINE_CODE`에 저장한다.
- `WORKSTAGE_CODE`는 기존 계약대로 필수이며, 설비가 없을 때에도 작업지시에서 초기화된 공정코드를 저장한다.
- 작업지시 write-back에서도 설비코드만 `NULL`로 저장하고 공정코드는 유지한다.

## 데이터 흐름

1. 사용자가 작업지시의 실적등록 패널에서 신규 실적을 연다.
2. 폼은 작업지시의 설비코드가 없으면 설비 미선택 상태로 시작하되 공정코드는 작업지시 값으로 유지한다.
3. 사용자가 설비를 고르지 않고 저장하면 프론트엔드는 설비코드 없이 요청한다.
4. 백엔드는 누락된 설비코드를 `NULL`로 정규화해 실적을 저장하고, 작업지시에도 설비 `NULL`과 기존 공정을 반영한다.

## 오류 처리

- 설비 미선택은 오류가 아니다.
- 공정코드 누락, 잘못된 실적수량, 완료 실적 수정 등 기존 오류 처리는 변경하지 않는다.
- DB 또는 API 오류는 기존 오류 메시지 전달 방식을 유지한다.

## 검증

- 프론트 구조 테스트: 설비 필수 표시와 저장 차단이 없고, 미선택 값을 선택사항으로 전송하는지 확인한다.
- 백엔드 DTO/서비스 테스트: `machineCode` 누락 요청이 검증을 통과하고 SQL bind에는 `null`, `workstageCode`에는 기존 공정이 전달되는지 확인한다.
- 프론트 전체 구조 테스트와 타입 검사, 백엔드 관련 Jest 테스트와 타입 검사를 실행한다.
- 개발 서버가 실행 중인 경우에만 실제 팝업에서 설비 미선택 저장을 확인한다. 서버는 에이전트가 임의 기동하지 않는다.

## 제외 범위

- 설비 콤보의 목록 조회 방식과 선택 UI 변경
- 설비 선택을 해제하는 별도 버튼 추가
- 실적수량 등 다른 필수 필드 완화
- 비가동 등록의 설비 필수 정책 변경
