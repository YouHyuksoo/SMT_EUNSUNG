 [이 문서를 읽는 법]
  Oracle은 컬럼 단위 변경 이력을 보관하지 않는다. 감사(audit)도 켜져 있지 않고,
  저장소에도 ALTER TABLE 스크립트가 남아 있지 않다(전체 검색 결과 0건).
  따라서 아래 내용은 다음 세 가지 근거로 역산한 것이다.
    (1) USER_OBJECTS.CREATED / LAST_DDL_TIME  — 테이블 단위 생성·최종변경 시각
    (2) USER_TAB_COLUMNS.COLUMN_ID 순서       — 뒤에 추가된 컬럼일수록 번호가 크다
    (3) 컬럼 주석과 git 커밋 이력             — 용도·시점 교차 확인
  ALTER 문은 "실제로 실행된 문장"이 아니라 현재 구조에서 역산한 재구성문이다.
  NOT NULL 로 표기된 컬럼은 그대로 실행하면 기존 행이 있는 테이블에서 실패한다.
  실제로는 NULL 허용으로 추가 → 값 채움 → NOT NULL 전환 순서였을 것이다.

==============================================================================
 5. 권고
==============================================================================

 앞으로 DB 구조를 바꿀 때는 적용 전에 ALTER 스크립트를 docs/sql/ 에 남기고
 적용한다. 그래야 git 이력으로 "언제 무엇을 왜 바꿨는지"가 추적된다.
 이번처럼 사후 역산하면 시각과 컬럼은 알 수 있어도 변경 사유와 일괄 변경의
 내용(3번 항목)은 복구할 수 없다.
